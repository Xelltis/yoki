# Googleと連携する

設置した卓予定で、Googleでのログインと、Googleカレンダーとの連携を使えるようにする手順です。どちらも任意で、設定しなくても卓予定は使えます。

| 機能 | 使う人から見えるもの |
|---|---|
| Googleでログイン | 入口の「Googleでログイン」と、設定の画面の「ログインの方法」 |
| Googleカレンダーとの連携 | 設定の画面の「カレンダー連携」。参加する卓を本人のGoogleカレンダーに書き込み、本人の予定から予定表に × と △ を入れる |

2つの機能が使うのは、同じOAuthクライアントです。下の手順で、クライアントID・クライアントシークレット・鍵の3つをそろえたときだけ、画面に出ます。購読URLと、卓ごとの「Googleカレンダーに追加」は、この設定が無くても使えます。

Googleでログインできるようになっても、利用者そのものはDiscordのアカウントのままです。Googleのアカウントは、Discordのアカウントに結びつけた、もう1つの入り口になります。グループに入れるかを決めるのは、Discordのサーバーです。

## 1. Google Cloudでプロジェクトを作る

[Google Cloudのコンソール](https://console.cloud.google.com/) でプロジェクトを作り、「APIとサービス」でGoogle Calendar APIを有効にします。

## 2. OAuth同意画面を作る

同意画面には、次を入れます。

| 欄 | 入れるもの |
|---|---|
| アプリ名 | 卓予定など |
| サポートのメール | 問い合わせを受けるメールアドレス |
| アプリのホームページ | 公開するアドレス |
| プライバシーポリシー | `<公開するアドレス>/privacy` |
| 利用規約 | `<公開するアドレス>/terms` |
| スコープ | `openid`・`email`・`https://www.googleapis.com/auth/calendar.events.owned` |

`calendar.events.owned` は、本人が持つカレンダーの予定だけを触れるスコープです。卓予定はメインのカレンダーしか触らないので、共有されたカレンダーにも届く `calendar.events` は求めません。

## 3. OAuthクライアントIDを作る

種類は「ウェブ アプリケーション」にします。承認済みのリダイレクトURIには、`<公開するアドレス>/auth/google/callback` を入れてください。クライアントIDとクライアントシークレットを控えます。

## 4. 鍵を作る

連携した人のrefresh tokenは、この鍵で暗号にしてD1に置きます。鍵は、ランダムな32バイトをbase64にしたものです。ターミナルが使えるなら `openssl rand -base64 32` で作れます。

鍵を替えると、連携していた人は全員、連携し直しになります。いちど決めたら替えないでください。

## 5. 値を入れる

ボタンで設置したなら、Cloudflareの画面のWorkers（Workers & Pages）で `yoki` を開き、「Settings」→「Variables and Secrets」に次の3つを足してください。種類は、3つとも「Secret」にします。保存すると、すぐに使えるようになるはずです。

| 名前 | 中身 |
|---|---|
| `GOOGLE_CLIENT_ID` | クライアントID |
| `GOOGLE_CLIENT_SECRET` | クライアントシークレット |
| `GOOGLE_TOKEN_KEY` | 4で作った鍵 |

GitHub Actionsで公開しているなら、environment「production」に、変数 `YOKI_GOOGLE_CLIENT_ID` と、秘密 `GOOGLE_CLIENT_SECRET`・`GOOGLE_TOKEN_KEY` を入れます。入れたら、Actionsの「アプリを公開する」で公開し直してください。

## だれでも使えるようにする

Googleの同意画面は、初めは「テスト」の状態です。テストのあいだは、同意画面の「テストユーザー」に足した人（100人まで）だけが、ログインと連携をできます。

Googleでのログインが求める `openid`・`email` は、機密性の高いスコープではありません。同意画面の公開ステータスを「本番環境」にすれば、だれでもGoogleでログインできるようになります。

カレンダーとの連携が求める `calendar.events.owned` は、Googleの「機密性の高いスコープ」です。だれでも連携できるようにするには、Googleの審査（OAuthアプリの確認）を受けてください。審査が済むまでは、連携のときに「確認されていないアプリ」の注意が出ます。テストのあいだに連携した人は、refresh tokenが7日で切れるので、連携し直しになります。

審査で見られるのは、プライバシーポリシーにGoogleのデータの扱い（受け取るもの・使い道・Limited Useに従うこと）が書いてあるかです。卓予定の既定の文には書いてあります。運営の管理画面で本文を直したときは、この部分を消さないように気を付けてください。

## 卓予定が守ること

連携した人のrefresh tokenは、画面・ログ・運営の管理画面のどこにも出しません。Googleから受け取るのは、アカウントのIDとメールアドレスと、予定の時間など、予定があるかを決めるのに要る欄だけです（予定の名前や中身は受け取りません）。

本人が連携を外したときと、運営者が利用者を消したときは、書き込んだ予定を消し、Googleの許可を取り消してから、控えを消します。
