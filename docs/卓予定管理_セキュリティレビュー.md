# 卓予定管理 セキュリティレビュー

2026-10-03。外部のレビューで「いまの段階ではセキュリティに問題があり、作りを大幅に変える必要がある」と言われた。それを受けて、ver53 の `Code.gs` と `Console.html` を読んで確かめた。外部レビューの具体的な指摘はまだ受け取っていない。

## 見立て

すぐ直すべき穴は 1 つ（MUST-1）で、作りを変えずに数十行で塞げる。

「大幅に変える」が要るのは、次の 3 つを変えたい場合である。どれも、少人数の身内で使う前提で選んだ作りになっている。

- 本人確認は名乗りだけ（SHOULD-1）
- 合言葉はみんなで 1 つ（SHOULD-1・SHOULD-3）
- 作者のアカウントで動く（SHOULD-5）

作者のアカウントで動く件は、テンプレート配布（`docs/卓予定管理_配布準備_案.md`）にすれば、各グループが自分のアカウントで動かす形になる。作者の側の不安はこれで消える。名乗りの件は、一人ずつの招待リンクに変えれば Google ログインなしで直せる。中規模の改修で、全面的な作り直しにはならない。

## MUST-1. 合言葉を通らずに、通知を止める・Discord に送る関数を呼べる

```
186  function refreshAll() {
195  function installTriggers() {
204  function removeTriggers() {
365  function dailyNotify(e) {
492  function notifyTomorrowNow() {
561  function testDiscord() {
```

Apps Script のウェブアプリでは、`Code.gs` の名前が `_` で終わらない関数を、画面から `google.script.run` で誰でも呼べる。画面に出すボタンとは関係がない。合言葉の確認（`authFor_`）は画面用の関数にだけ入っていて、シートのメニュー用と自動通知用の関数には入っていない。

ウェブアプリの URL を知っていれば、合言葉を知らない人でも、ブラウザの開発者ツールから次のことができる。URL は募集や日程調整の知らせで Discord に流しているので、チャンネルにいる人は誰でも知っている。

- `removeTriggers()`：自動通知のトリガーを消す。開催前の知らせが黙って止まる。最後の `getUi()` で例外になるが、消したあとなので戻らない。
- `notifyTomorrowNow()`・`testDiscord()`：Discord に知らせを送る。明日の卓の知らせは参加者をメンションするので、何度も呼ばれると通知の嵐になる。
- `dailyNotify({ testNow: …, triggerUid: 'x' })`：「いま」をずらして見回りを走らせる。送る日でない知らせを送り、「送った」の印を付けるので、本来の日に届かなくなる。
- `refreshAll()`・`setup()`・`installTriggers()`：重い描き直しやトリガーの作り直し。何度も呼ぶと、ほかの人の書き込みが順番待ちで詰まる。

卓や都合のデータを読む・書き換える・消すことはできない。それらの関数は合言葉を確かめている。

直し方の候補は次の 2 つで、両方とも入れる。

1. シートのメニュー用の関数は、先頭で「シートの画面から呼ばれたか」を確かめる。ウェブアプリから呼ばれると `SpreadsheetApp.getUi()` が例外になるので、何かを書く前にこれを呼んで止める。
2. 自動通知用の関数（`dailyNotify`・`refreshIfDirty`）は、渡された `triggerUid` が、このスクリプトに実在するトリガーの ID かを `ScriptApp.getProjectTriggers()` で確かめる。合わなければ何もしない。テスト用の `testNow`・`testHour` は、中身を `_` 付きの関数に分けてそちらだけが受け取る。

## SHOULD-1. 本人確認は名乗りだけ。合言葉を知っていれば、誰の名前でも入力できる

```
1136 function requireSelfOrAdmin_(form, name) {
       const me = String((form && form.me) || '').trim();
       if (me && me === String(name || '').trim()) { authFor_(form); return; }
```

「自分のぶん」かどうかは、画面が送ってくる `me`（上の「あなた」で選んだ名前）が対象の名前と同じかだけで決めている。合言葉はみんなで 1 つなので、サーバーには誰が操作したかを確かめる手段がない。合言葉を知っている人は、`me` を書き換えれば、ほかの人の都合・日程調整の回答・参加希望を入れられる。

身内で使う前提の作りで、メンバー同士を疑わないなら問題にならない。外部レビューの「大幅に変える」は、たぶんこの点を指している。

直し方の候補：管理者がメンバーごとに招待リンク（その人だけの証）を作り、サーバーは証から名前を引く。`me` は画面から受け取らない。Google ログインは要らない。

## SHOULD-2. ログインの失敗回数が全員で共通

```
1083 function loginThrottle_() {
1090 function loginFailed_() {
```

失敗の回数はスクリプトのプロパティに 1 つだけ持っている。合言葉を知らない人がわざと 10 回間違えると、その後 10 分は、正しい合言葉を入れた人も入れなくなる。繰り返せば、ずっと入れない状態にできる。管理者の合言葉（`1151`）も同じ作り。

直し方の候補：失敗は端末ごとに数える（画面が端末の ID を送り、ID ごとに数える）。全体の上限は、それより大きい数にして残す。

## SHOULD-3. ログインの証に期限が無い

```
1053 function tokenOf_(ver) { return sha_(secret_() + '|' + ver); }
```

証は「秘密の値」と「合言葉の版」から作る 1 つの値で、全員が同じものを持つ。期限は無く、合言葉を変えるまで使える。端末をなくしたり、人に見られたりしたときは、合言葉を変えて全員に入れ直してもらうしかない。

直し方の候補：SHOULD-1 の招待リンクにすれば、証が一人ずつに分かれ、その人の証だけを取り消せる。期限（例：90 日）を付けて、切れたら入れ直す形にもできる。

## SHOULD-4. 最初の合言葉は早い者勝ち

```
1235 function setInitialPassword(form) {
       if (hasPassword_()) throw new Error('合言葉はもう決まっています。…
```

ウェブアプリを公開してから合言葉を決めるまでのあいだは、URL を開いた人が誰でも最初の合言葉を決められる。いまの本番では決め済みなので影響はない。テンプレートとして配ると、立てる人ごとにこの隙間ができる。

直し方の候補：配布版では、ウェブアプリから最初の合言葉を決める入口を閉じる。シートのメニュー（`setWebPassword`）で決めてから公開する流れにする。

## SHOULD-5. 作者のアカウントで、スプレッドシート全般の権限を持って動く

```
1746 function ss_() {
       …
       return SpreadsheetApp.openById(id);
```

ウェブアプリは「自分として実行」で、誰が操作しても作者のアカウントで動く。`openById` を使っているので、スクリプトが求める権限は、このシートだけにとどまらず「作者のすべてのスプレッドシート」に及ぶ。いまのコードはこのシートしか開かないが、コードに穴があれば作者の権限で動く。最初の依頼にあった「管理側のログインが怖い」は、この点を指している。

直し方の候補：テンプレート配布にして、各グループが自分のアカウントで動かす（作業は配布準備の案のとおり）。あわせて `appsscript.json` に `oauthScopes` を書き、権限を必要なものに絞る。ウェブアプリから `getActiveSpreadsheet()` で自分のシートが取れれば `spreadsheets.currentonly` まで絞れる。取れるかどうかは確かめていない。

## IMO-1. 合言葉のハッシュが SHA-256 の 1 回だけ

```
1044 function sha_(text) { …computeDigest(…SHA_256…) }
```

塩は付けているが、ハッシュは 1 回なので、ハッシュの値が漏れれば 8 文字の合言葉は総当たりで割り出せる。ハッシュはスクリプトのプロパティにあり、見られるのはスクリプトの編集者だけなので、実害は小さい。気になるなら、ハッシュを数千回重ねる。

## FYI-1. 合言葉を知らない人に、卓やメンバーのデータは渡らない

`getConsoleData`（`1297`）は、証が無ければ題名と URL だけを返す。書き込みの関数もすべて合言葉を確かめる（MUST-1 の関数は除く）。Discord の Webhook URL は、画面用のデータでは伏せている。

## FYI-2. 画面に差し込む文字はエスケープしている

`Console.html` の `innerHTML` のうち、人が入力した文字（卓の名前・メンバー名・メモ・通知ログ）を差し込む箇所を抜き取りで見た。すべて `esc()` を通していた。全数は確かめていない。Apps Script の画面は Google の別ドメインの iframe で動くので、仮に漏れがあっても、取られうるのはこの画面の証だけになる。

## 機械的に確かめたこと

`Code.gs` の関数のうち、名前が `_` で終わらないもの（画面から呼べるもの）を数え、合言葉の確認を通るかを、`…Locked_` への委譲もたどって調べた。確認を通らない 17 個（`doGet` を含む）のうち、実害のあるものを MUST-1 に挙げた。`seedSample` はシートを整えたあと `getUi()` で止まり、データは足さない。`onOpen`・`onEdit` は、ウェブアプリから呼んでも引数が範囲にならないので害はない。`setWebPassword`・`setAdminPasswordFromSheet`・`showWebAppUrl` は最初に `getUi()` で止まる。`login`・`setInitialPassword` は入口なので確認が無いのが正しい。
