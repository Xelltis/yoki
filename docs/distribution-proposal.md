# 卓予定管理 配布準備の案（テンプレート配布）

2026-10-01。利用者から「管理側のログインが怖いので、各自で立てられる形で配ってほしい」と頼まれた。これを受けて、スプレッドシートをテンプレートとして配る形にする。

## 1. いまの形と、配布したあとの形

| | いま | 配布後 |
|---|---|---|
| データの置き場 | 作者（yana.enoki）のドライブ | 立てた人のドライブ |
| 動くアカウント | 作者のアカウント（ウェブアプリは「自分として実行」） | 立てた人のアカウント |
| 作者から見えるもの | 全部 | 何も見えない |
| 入り方 | 共通の合言葉 | 同じ（立てた人が合言葉を決めて、メンバーに URL と一緒に渡す） |

「作者のアカウントに全部が乗っている」状態がなくなることが、今回の依頼への答えになる。

## 2. コピーで引き継がれるもの・引き継がれないもの

スプレッドシートを「コピーを作成」すると、次のようになる。

- 引き継がれる：シート（中身ごと）、紐づいたスクリプト（`src/` の server と client のファイル）
- 引き継がれない：ウェブアプリの公開（デプロイ）、自動通知のトリガー、スクリプトのプロパティ（合言葉のハッシュ・管理者の合言葉）

合言葉とトリガーが引き継がれないのは都合がよい。困るのはデプロイで、これは立てる人が自分で押すしかない（スクリプトから自動ではできない）。

## 3. やること

### 3-1. 配布用の原本を別に作る（必須）

本番のシートをコピーして配ってはいけない。本番には次のものが入っている。

- 「設定」シートの Discord Webhook URL（持っている人は誰でもそのチャンネルに書き込める）
- 「メンバー」シートの Discord ユーザーID
- 卓の予定、通知ログ、日付メモ

新しい空のスプレッドシートに clasp で同じスクリプトを送り、「初期設定」だけを走らせたものを原本にする。原本のスクリプト ID は本番と別に控える。

### 3-2. はじめの設定を 1 本の流れにする（必須）

いまはメニューに項目が並んでいるだけで、順番を知らないと立てられない。シートを開いたときに、未設定なら次の順で案内する窓を出す。

1. 初期設定（シートを作る）
2. ウェブアプリとして公開する（手順を画面で案内。ここだけは本人が押す）
3. 合言葉を決める
4. 管理者の合言葉を決める
5. Discord の Webhook URL を入れる（任意）
6. 自動通知を ON にする（任意）

公開が済んだかどうかは `ScriptApp.getService().getUrl()` で分かるので、済んだ段は飛ばせる。

### 3-3. 立てる人向けの手引き（必須）

つまずくのは次の 2 か所なので、画面の切り抜きを付けて書く。

- 「このアプリは Google で確認されていません」の警告。自分で作ったコピーを自分が動かすので安全だと説明し、「詳細 → 安全ではないページに移動」で進める手順を載せる。
- デプロイの画面。「次のユーザーとして実行：自分」「アクセスできるユーザー：全員」を選ぶ。

手引きは md/その他/ に置き、配る版は Tutorial.html と同じ見た目の HTML にする。

### 3-4. 更新の届け方（2026-10-01 に A と決定）

コピーした先には、作者の更新が届かない。次の 2 つのどちらかを選ぶ。

| | A. 貼り替えで更新 | B. ライブラリで更新 |
|---|---|---|
| 仕組み | 新版が出たら、立てた人が `src/` のファイルを貼り替えて公開し直す | 配るコピーには薄い呼び出しだけを置き、本体は作者のライブラリにする |
| 更新の手間 | 立てた人ごとに毎回 | 作者が版を上げれば全員に届く |
| 信頼 | 配った時点のコードだけが動く | 作者があとから中身を変えられる。「作者が怖い」という今回の依頼とぶつかる |
| 作業量 | 小さい（版番号を画面に出し、更新手順を書く） | 大きい（構成の組み直し） |

A にする（依頼の趣旨に合うため）。画面の隅に版番号を出して、手引きに「新しい版の入れ方」を書く。

### 3-5. 配る前に決めること

- 配り方：コピー用の URL（`…/copy`）をどこに出すか（X、BOOTH、GitHub など）
- 利用条件：無保証であること、改変・再配布をしてよいか
- 問い合わせ先
- 名前（広報では「Yoki」を使っている）

## 4. 進める順番

1. 3-1 配布用の原本を作る
2. 3-2 はじめの設定の窓
3. 3-3 手引き
4. 知り合い 1 人に、手引きだけを見て 0 から立ててもらう（ここで詰まった所を直す）
5. 3-5 を決めて公開

3-4 は A に決まったので、2 のときに版番号も画面に出す。
