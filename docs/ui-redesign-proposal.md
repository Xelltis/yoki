## 2. 再設計の原則

1. **入口は 3 つ。** ホーム・カレンダー・みんなの空き。メンバーと設定はその下に置き、ヘルプはナビから外す。
2. **最初に出るのは「あなたのやること」。** 人によって中身が変わる 1 行 1 アクション。読むものではなく押すもの。
3. **卓のことは 1 枚のシートで完結する。** 詳細・日程調整・参加確認・編集・削除を、右から出る 1 枚に集約。下端に「いま押すべき 1 つ」を固定する。
4. **設定は表にする。** 散らばった通知の設定を「知らせ × 送り先 × タイミング × 送る」の 1 枚に畳む。URL の管理は別の窓へ逃がす。
5. **色は状態にだけ使う。** 募集＝橙、調整中＝紫、開催＝青、終了＝灰、中止＝赤。淡い地に濃い字のソフトトーンで、原色は並べない。

## 4. 画面ごとの設計

### ホーム
- **あなたのやること**：日程調整の未回答、参加希望を出せる募集、GM としての次の一手、今夜の卓。1 行につきボタンは 1 つ。何もなければ「卓をつくる」だけを出す。
- **これからの卓**：日が決まっているものを 5 件。左の細い縦線が状態の色。右に「GM／参加／知らせ済み」の札。
- **進行中**：募集と日程調整のカード。「次にすること」を 1 文で書き、主ボタンは GM と参加者で出し分ける（GM には「日を決める」、参加者には「参加希望を出す」）。

### カレンダー
- 月のグリッドに、**卓**と**空き**の 2 つのレイヤーを重ねる（セグメントで切り替え）。
- 募集・調整の期間は、日ごとの札ではなく**週をまたぐ 1 本の帯**で描き、名前は期間の初日か週の頭にだけ書く。15 日間の募集が 15 個の札になる問題を消す。
- 凡例は 4 つだけ（全員空き・開催・募集の期間・日程の候補）。
- 日を押すとシートが開き、その日の卓・候補日・「この日に卓をつくる」が出る。

### みんなの空き
- PC は表を残す。自分の列は色を変えて固定し、押すと 空欄 → △ → × と回る。ほかの人のマスは押せない。
- スマホは**日ごとのリスト**に変える。1 行につき ◯ △ × の 3 つのボタンを大きく置く。卓に入っている日は「参」「GM」の札にして、押せないことを見せる。
- 絞り込みはチップ（土日祝だけ・全員空きだけ・卓で絞る）。

### 卓のシート（右から出る 1 枚）
- 上に **募集 → 調整中 → 開催 → 終了** のステッパー。いまどこかを 1 本の帯で示す。
- GM・参加・参加希望・興味あり・場所・シリーズ・メモ。
- 調整中なら候補日を、回答の本数のバーつきで並べ、その場で ◯ × を押せる。
- 知らせの予定（「前日 20 時台に送ります」「期間の前日に GM へ」）をここに出す。設定を見に行かなくても、この卓に何が飛ぶか分かる。
- 下端に主ボタン 1 つ＋「編集」、右端に控えめな「削除」。

### 設定
- 左に 5 区分（知らせ・この卓予定・この端末・入り口と合言葉・送信の記録）。
- **知らせ**は 1 枚の表。行＝知らせの種類（開催前・募集・期間前の催促・開始直前・登録変更）、列＝送り先・タイミング・ON/OFF。
- Webhook URL は表に出さず、「チャンネルを管理」の窓で名前（`#卓の告知` など）に紐づける。シリーズごとの違いは「上書き」として別の窓に畳む。
- この案では、設定画面の縦は 525px（いま 2975px）。

## 5. デザイントークン

色は OKLCH で持ち、明暗で同じ意味になるよう対で定義する。

| 種類 | 明 | 暗 |
|---|---|---|
| 背景 / 面 | `oklch(98.4% .004 260)` / `oklch(100% 0 0)` | `oklch(17.5% .012 260)` / `oklch(21.5% .013 260)` |
| 文字 / 副 | `oklch(25% .018 260)` / `oklch(50% .015 260)` | `oklch(94% .006 260)` / `oklch(74% .012 260)` |
| 差し色 | `oklch(52% .11 245)` | `oklch(72% .10 245)` |
| 募集 | 字 `oklch(48% .11 62)` ／ 地 `oklch(96.5% .035 62)` | 字 `oklch(85% .09 62)` ／ 地 `oklch(30% .045 62)` |
| 調整中 | 字 `oklch(47% .12 300)` ／ 地 `oklch(96.5% .03 300)` | 字 `oklch(85% .08 300)` ／ 地 `oklch(30% .045 300)` |
| 開催 | 字 `oklch(46% .10 245)` ／ 地 `oklch(96.5% .028 245)` | 字 `oklch(85% .07 245)` ／ 地 `oklch(29% .04 245)` |

- **角丸**: 6 / 10 / 14 / 18px と丸（`999px`）。カードは 18、ボタンと入力は 10。
- **影**: 2 段だけ。面は `0 1px 2px`、浮くもの（シート・パレット）は `0 8px 24px`。グラデーションと発光は使わない。
- **余白**: 4px の倍数。密度を 3 段（密・標準・広）で切り替え、行の高さ（34 / 44 / 52px）と字の大きさ（14 / 15 / 16px）が連動する。
- **字**: Inter → Noto Sans JP → system-ui。数字は `tabular-nums`、日本語は `palt`。
- **動き**: 150ms、`transform` と `opacity` だけ。`prefers-reduced-motion` で止める。

## 6. キーボードと読み上げ

- `⌘K` / `Ctrl+K` / `/` でパレット、`N` で卓をつくる、`Esc` で閉じる、`↑↓` と `Enter` で選ぶ。
- シートとパレットは `<dialog>`。Esc と背景クリックで閉じ、フォーカスは中に閉じる。
- 状態の切り替えは `aria-pressed`、ON/OFF は `role="switch"` と `aria-checked`、現在地は `aria-current`。
- 色だけで意味を伝えない（状態は札の文字、空きは ◯ △ ×）。
- 「本文へ」のスキップリンクを置く。

## 8. ver2 — 原盤に差し込む 2 画面

`mock/ui2026-v2.html` が、実際に入れる範囲のモック。
`mock/ver2-overlay.html`（差し替えの中身）を、`mock/pages.js` がアプリ（開発サーバーで動く本物の画面）の末尾に差し込んで組む。原盤の中身は 1 文字も書き換えていない。

```
npm run dev     （http://localhost:5173/mock/ui2026-v2.html を開く）
```

### 8-1. メンバーの予定

残すもの（原盤のまま）: 見出し、日が未定の卓の帯、「まとめて入れる」「卓をまとめて変える」の折りたたみ、「卓の多い人を左に」。

差し替えるもの。

- **絞り込みは表の上のチップに出す。** 原盤では折りたたみの中にあり、開かないと何で絞れるかが分からなかった。「土日祝だけ」「全員空きだけ」「自分の列だけ」「卓で絞る」の 4 つを、常に見える形で置く。もとの折りたたみは畳んだまま残す。
- **自分の列に色を付ける。** 地と見出しに同じ淡い色を敷くだけで、どこを押せばよいかが分かる。
- **マスをボタンにする。** 押すと 空 → △ → × と回る。ほかの人のマスは押せない（`disabled`）。読み上げには「10/3（土） ひより 参加できる」のように読ませる。
- **卓に入っている日は「参」「GM」の札。** 押せないことが形で分かる。
- **メモの鉛筆は自分のマスだけに出す。** 原盤の `openMemo()` をそのまま呼ぶ。メモのある日は左上に点を出す。
- **全員が空いている日は、卓の欄にうっすら色を敷く。** 日を探すときの手がかりになる。
- **狭い画面（760px 未満）は日ごとのリストに変える。** 1 行に ◯ △ × の 3 つのボタンと鉛筆。横スクロールしないで打てる。

### 8-2. 設定

- **左に 5 区分、右に中身**（知らせ／この卓予定／この端末／入り口と合言葉／送信の記録）。原盤は 10 枚のカードが縦に 2975px 並んでいた。ver2 では 809px。
- **知らせは 1 枚の表にまとめる。** 行＝知らせの種類（開催前・期間前の催促・開始直前・登録変更・募集と参加確認）、列＝送り先・タイミング・ON/OFF。
- **Webhook URL は表に出さない。** 「チャンネル（Discord の Webhook URL）」と「シリーズごとの上書き」の折りたたみに畳み、中身は原盤のカードをそのまま入れている。
- 送り先の列には、いまの設定から「基本のチャンネル」「事前通知のチャンネル」「募集のチャンネル」のどれに届くかを出す。選び直すのは折りたたみの中。
- 表のスイッチと数値は、畳んである原盤のカードの入力とボタンを動かして保存する。つまり**保存の経路は原盤のまま**で、見せ方だけが変わっている（ver2 のモックでも実際に保存が走る）。

### 8-3. 本体へ移すときの順序

1. **設定の 2 ペインと知らせの表** — 2026-09-26 に ver47 で本体へ入れた。保存の経路は変えず、見せ方だけを差し替えてある。設定タブの縦は 2975px から 732px になった。あわせて用語をそろえ、事前通知は「開催前の知らせ」、開始前の知らせは「開始直前の知らせ」、セッション名は「卓の名前」になった（旧い設定シートの項目名は、シートを整え直すときに自動で移る）。
2. **メンバーの予定の表**。`renderAvail()` を置き換える。折りたたみと一括操作はそのまま。まだ入れていない。
3. **スマホの日ごとのリスト**。760px を境に、表とリストを出し分ける。まだ入れていない。
4. ver1 の残り（ホーム・シート・⌘K）は入れない。必要になったときに、この文書を読み直す。

本体へ入れたぶんは ver2 のモックからは外してある（モックは残りの「メンバーの予定」だけを差し替える）。

## 9. ver1 のモックでやっていないこと

- 保存・送信・ログイン。押すと「モックです」の吹き出しが出るだけ。
- シリーズの引き継ぎ、複数日のまとめ登録、予定メモ、ユドナリウム連携、印刷。
- 実データの量（卓が 100 件を超えたときの並びと読み込み）。
- 実機の Apps Script への組み込み（`Console.html` は 1 ファイルで配るため、この構造をそのまま移すと CSS と JS がいまの倍近くになる。移すなら第 8 節の順で、1 つずつ）。

## 10. 確かめたこと（ブラウザ）

### ver2（32 項目すべて OK）

- 原盤の上タブ・カレンダー・募集調整タブ・下のタブ（スマホ）は、差し替えの前と同じに動く。
- メンバーの予定: チップで絞れる（土日祝だけで 60 → 21 行、自分の列だけで 3 列）。自分のマスを押すと印が変わり、`setAvailability` が走ってデータに入る。ほかの人のマスは押せない。もとの表は消さずに隠してある。
- 設定: 5 区分に切り替わり、知らせの表は 5 行。縦は 809px（原盤 2975px）。「開始直前の知らせ」のスイッチを押すと実際に保存され、表の見た目も追従する。折りたたみを開くともとの Discord のカードが出る。「送信の記録」にもとの記録の表が入る。
- 明暗どちらの配色でも崩れず、PC でもスマホでも横に溢れない。スマホでは日ごとのリストになり、その場で印を打てる。
