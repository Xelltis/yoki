# 卓予定管理（Google スプレッドシート + Apps Script）

対象: TRPG の卓（セッション）の予定を、複数人で共有するスプレッドシート
目的: カレンダーで予定を見て、卓の一覧と参加状況を把握し、開催前に Discord へ自動で知らせる
置き場: `trpg-tool/session-scheduler/`

## 結論

作った。見る入口は 2 つ、書く入口は 1 つ。スプレッドシートは Apps Script がタブを描き直す掲示板。ウェブアプリは URL を開くとブラウザに出る画面で、タブはカレンダー・募集・調整・メンバーの予定・メンバーの登録・設定の 5 つ。卓の登録と変更は、カレンダーから開く窓で行う。卓の登録と都合の入力はウェブアプリで行う。スマホでも使える。データはどちらも同じスプレッドシートにある。

要件との対応は次のとおり。

| 要件 | 実装 |
|---|---|
| カレンダー形式 | 「カレンダー」タブ。シートは今月から 2 か月分（設定で 1〜12 か月）、ウェブアプリは月送りで何か月でも見られる |
| 複数人で運用 | ウェブアプリの URL と合言葉を配る。シートを編集者として共有すれば、シート側のメニューも全員が使える |
| 合言葉 | 画面を開くと全員共通の合言葉を求める。一度入れたブラウザはログアウトするか合言葉が変わるまで二度と求めない。合言葉を変えると全員が入れ直しになるので、外した人はそこで締め出せる |
| セッション登録（名前・GM・参加者・日・時間） | ウェブアプリの「登録」タブ。「セッション」シートを直接直してもよい |
| 別タブで一覧 | シートの「一覧」タブ。募集・調整中・開催の卓を開催日順に並べ、「あと何日」を色で示す。ウェブアプリでは「メンバーの予定」タブの「卓をまとめて変える」の一覧がこれを兼ねる |
| 画面上の通知 | ウェブアプリのカレンダー右上「卓予定」欄、シートの「お知らせ」欄、開いたときの吹き出し、一覧の行の色 |
| Discord 連携と開催前の知らせ | Webhook に投げる。開催日の何日前の何時台に送るかを決めると、その日時に卓の知らせを 1 通にまとめて送る（既定は前日の 20 時台）。開催前の知らせと募集の知らせは、種類ごとに別のチャンネルへ分けられる。シリーズごとにも、送るチャンネル（基本のチャンネルと両方にもできる）と日時を変えられる。Discord のユーザーID があればメンションする。カレンダーで日を選ぶと出る「Discord に通知」ボタンで、卓 1 件の案内をその場で送れる |
| 参加者全員の都合がいい日のハイライト | 「メンバーの予定」タブ（シートでは「都合」）に、各自が都合の悪い日だけ △× を入れる。空欄は参加できる扱い。その日の卓に入っている人は「参」「GM」が自動で付く。カレンダーで卓を選ぶと、その卓の参加者の誰も △× を付けていない日が緑になる |
| 全体管理 | 「メンバーの予定」タブの予定表で、名前の下に GM をしている卓数と参加している卓数が出る。卓に入っている人ほど左に並ぶ。「卓をまとめて変える」を開くと、卓の一覧から複数選んでまとめて変えられる |
| 日付ごとのメモ | カレンダーの日にメモを書ける。卓と関係のない予定もここに置く |
| 予定へのメモ | 「メンバーの予定」の自分のマスに、△×とは別の一言（「21 時から」「午前だけ」）を添えられる。マスには点だけ付き、マウスを載せると出る。ほかの人にも見える |
| 終わった卓の後始末 | 開催日の当日に「開催」、過ぎたら「終了」に自動で変わる。カレンダーには灰色で残る |
| 期間前の催促 | 募集中・調整中のまま期間の始まる前日になると、GM に Discord で知らせる。設定で ON / OFF |
| 開始直前の知らせ | 卓の当日、開始の◯分前に GM と参加者へ Discord で知らせる。設定で ON / OFF（既定は OFF）と分を決める |
| 管理者 | シートを開く・ほかの人のぶんを入れる・メンバーと設定を変える・卓を消す、を管理者だけにできる。管理者は何人でもよく、最初の合言葉を決めた人が最初の管理者 |
| 参加者の募集 | 状態を「募集」にすると、開催日の代わりに「10/3〜10/17」のような開きたい期間を持つ。「募集・調整」タブで各自が「参加希望」「興味あり」を付けられ、状態が「調整中」か「開催」になると参加希望の人はそのまま参加者になる |
| 日程調整 | 調整中の卓で「日程を調整する」を押して候補日を選ぶと、GM と参加者に Discord で知らせる。各自が「募集・調整」タブで候補日ごとに ◯ か × を押す。全員が答えると GM に Discord で知らせ、GM が「この日に決める」で選んだ日が開催日になる（状態は「開催」になる）。どこでもよければ「どの日でもいい」で全部にまとめて ◯ を付けられる |
| 参加の確認 | 「募集・調整」タブの「興味ありの人に聞く」で、興味ありの人にメンションした確認文を Discord に送る。返事は各自が同じタブの「参加希望」で返す |
| キャンペーン（何回かに分けて開く卓） | 卓に「シリーズ」名を付けて束ねる。登録でシリーズを選ぶと直前の回から GM・参加者・時間・場所・メモを引き継ぎ、名前は「シリーズ名 #3」と進む。開催日を何日か並べて一度に登録できる。カレンダーの日からも「この日に続きを登録」で選べる |

Google 側の実機ではまだ動かしていない。Apps Script の API を模したモックで、初期設定から登録・通知・トリガー・ウェブアプリの入口まで通しで検証した。ブラウザ画面は Chromium で描画して確かめた。どちらも後述する。実機で最初に確かめる点も後述する。

## 導入手順

画面の文言は Google と Discord の現行の画面を記憶で書いている。多少違っていても、同じ意味の項目を探せば辿れる。

1. Google スプレッドシートを新規に作る。名前は何でもよい。
2. 「ファイル → 設定 → 全般」でタイムゾーンを「(GMT+09:00) 東京」にする。
3. 「拡張機能 → Apps Script」を開く。
4. 最初からある `コード.gs` を消す。左のファイル欄の「＋ → スクリプト」で、`src/server/` の 18 個のファイルを、パスつきの同じ名前（`server/Config` など。拡張子 `.gs` は自動で付く）で作り、それぞれの中身を貼る。
5. 「＋ → HTML」で、`src/client/` の 6 個のファイルを同じように作って貼る（`client/Console`・`client/ConsoleCss`・`client/ConsoleJs`・`client/Tutorial`・`client/TutorialCss`・`client/TutorialJs`）。名前が 1 文字でも違うと画面が出ないので、写し間違いに気をつける。ファイルが多いので、clasp で送るほうが早くて確実（後述）。
6. 左の歯車（プロジェクトの設定）で、タイムゾーンを「Asia/Tokyo」にする。`src/appsscript.json` を貼りたければ、同じ画面の「appsscript.json をエディタで表示する」を ON にする。任意。
7. 保存（Ctrl+S）してスプレッドシートに戻り、ページを再読み込みする。メニューに「卓予定」が出る。
8. 「卓予定 → 初期設定（シートを作る）」を実行する。初回は承認を求められる。自分のアカウントを選び、「詳細」→「（安全ではないページ）に移動」→「許可」と進む。自分で作ったスクリプトなので、この警告は出て当然。
9. もう一度「初期設定」を実行する。8 枚のシートができる。
10. 卓に出る人の名前を入れる。ウェブアプリの「メンバーの登録」タブか、「メンバー」シートのどちらでもよい。Discord でメンションしたい人は、ユーザーID も入れる（取り方は画面に書いてある）。
11. 一緒に使う人を、スプレッドシートの「共有」で編集者として招待する。
12. Discord につなぐなら、Discord のチャンネルの編集 → 連携サービス → ウェブフック → 新しいウェブフック → 「ウェブフック URL をコピー」（設定タブで URL を貼る欄の横にある「？」にも、同じ手順が出る）。その URL をウェブアプリの「設定」タブに貼って「URL を保存」し、「接続テスト」で届くか確かめる。シートの「設定」シートに直接貼ってもよい。
13. 開催前の知らせを自動にするなら、ウェブアプリの「設定」タブで「開催日の [ ] 日前、[ ] 時台」を入れて「有効にする」。シートのメニュー「卓予定 → 自動通知を設定（毎時の見回り）」でもよい。シリーズごとにチャンネルや日時を分けるなら、同じ設定タブの「シリーズごとの通知」で決める。
14. シート側の表を 10 分おきに描き直すトリガーは、「初期設定」を実行したとき、または最初にウェブアプリから書き込んだときに自動で作られる。手で作る必要はない。

### ウェブアプリとして公開する

ブラウザから使う入口を作る。卓の登録と都合の入力はこの画面で行うので、この手順は飛ばせない。

1. Apps Script エディタの右上「デプロイ → 新しいデプロイ」。
2. 左上の歯車で種類を「ウェブアプリ」にする。
3. 「次のユーザーとして実行」は **自分**。「アクセスできるユーザー」は **全員**（Google のログインを求めない。守りは合言葉だけになるので、URL は仲間だけに渡す）。Google のログインも求めたいなら「Google アカウントを持つ全員」。
4. 「デプロイ」を押す。承認を求められたら、初期設定のときと同じく「詳細」から進む。
5. 出てきた「ウェブアプリ」の URL を自分で開く。最初は「最初の合言葉を決める」の窓が出るので、仲間と使う合言葉を 8 文字以上で決める。数字だけのものは避ける。決めるまで画面は出ない。シートのメニュー「卓予定 → ウェブアプリの合言葉を設定…」から決めてもよい。
6. URL と合言葉を仲間に配る。URL はあとからでも、シートのメニュー「卓予定 → ウェブアプリの URL を表示」で出る。

「自分として実行」にすると、開いた人はシートの編集権が無くても書き込める。書いたのが誰かは、画面右上の「あなた」で選んだ名前で記録する。

`src/` のファイルを貼り直したあとは、「デプロイ → デプロイを管理 → 鉛筆 → バージョン: 新バージョン → デプロイ」で更新する。URL は変わらない。ここを忘れると古い画面のまま動く。

### clasp で更新する（貼り直しをしない）

`clasp` は Google 公式の Apps Script 用コマンドで、手元のファイルをそのままスクリプトへ送れる。いまは次の形で設定済み（2026-09-18）。

- Node の持ち運び版を `C:\Users\enoki\tools\node-v24.21.0-win-x64` に置いた。インストーラではないので管理者権限は要らない。使うときは PATH の先頭にこのフォルダを足す。
- clasp は `package.json` で版を決めてあり、リポジトリで `npm install` すると `node_modules` に入る（2026-10-03 から。それまでは持ち運び版の Node に直接入れていた）。`npx clasp …` か `npm run push` で使う。
- `clasp login` で、シートを持つ Google アカウントの承認を済ませた。認証情報は `C:\Users\enoki\.clasprc.json` にあり、リポジトリには入らない。
- リポジトリ直下の `.clasp.json` にスクリプト ID と `"rootDir": "src"` を書いた（ひな形は `.clasp.json.example`）。スクリプト ID はエディタの「プロジェクトの設定」にある値で、`/exec` の URL に入っている文字列（デプロイ ID、`AKfycb` で始まる）とは別物。
- 送るのは `src/` の中だけ。`.claspignore` で、さらに `appsscript.json`・`server/*.js`・`client/*.html` の形に絞った。テスト・デモ・保管フォルダは送らない。`rootDir` を書き忘れると何も送らない。
- `src/appsscript.json` に、ウェブアプリの設定（自分として実行・全員）を入れた。消えると公開の設定が変わるので残しておく。

更新するときの流れは次のとおり。

```
npm run push
npx clasp redeploy <デプロイ ID> -d "卓予定管理シートverNN"
```

1 行目（中身は `clasp push --force`）で `src/` の中身（`appsscript.json` と `server/`・`client/` のファイル）を送る。スクリプト側は送った内容で上書きされるので、エディタで直接直した箇所があれば、先に `npx clasp pull` で手元へ取り込む。2 行目で新しい版を作り、公開中のウェブアプリをその版に差し替える。URL は変わらない。`npx clasp deployments` でデプロイの一覧と版を確かめられる。デプロイ ID はそこに出る（本番の ID はリポジトリに載せない）。

初めて clasp で送ったとき、スクリプト側のコードのファイル名は `コード.js` から `Code.gs` に変わった。中身は同じ役割で、動きは変わらない。

2026-10-03 にフォルダの構成を変え、`Code.gs`・`Console.html`・`Tutorial.html` を `src/server/`（役割ごとに 18 個）と `src/client/`（画面ごとに骨組み・CSS・JS）に分けた。この構成を初めて送ると、スクリプト側の `Code`・`Console`・`Tutorial` は消え、`server/…`・`client/…` に置き換わる。関数の名前は変えていないので、トリガーはそのまま動く。

画面を開いて「スクリプト関数が見つかりません: doGet」と出るなら、`server/WebApp` が送られていない（`rootDir` の書き忘れなど）か、貼ったあとに保存していない。「HTML ファイルが見つかりません」と出るなら、`client/` のファイルの名前が違う。

まず様子を見たいときは「卓予定 → サンプルデータを入れる」でメンバー 4 人と卓 4 件が入る。「セッション」「メンバー」の行を消せば元に戻る。

## 使い方

### ウェブアプリの画面

開くと合言葉を求められる。合えば画面が出て、そのブラウザは合言葉を覚える。以後はログアウトするか合言葉が変わるまで求めない。スマホと PC で 1 回ずつ入れれば済む。右上のログアウトのボタン（スマホでは設定タブの「この端末」にある「ログアウト」）で、そのブラウザの記憶だけを消せる。

PC では画面の上に 2 段のバーがある。上の段は、左にスプレッドシートの名前、右に読み込んだ時刻・「更新」・「あなた」・テーマ・ログアウト・シートを開くのボタン。下の段がタブで、選んでいるタブは明るく浮き、アイコンが水色になる。タブの並びの続き（設定の隣）には「はじめの 3 ステップ」と、その隣に使い方のページを開く「使い方」がある。幅が 1060 px 以下では、「はじめの 3 ステップ」は旗のアイコンだけになる（名前はマウスを重ねると出る）。バーは下へ送っても上に残る。スマホではバーが 1 段（時刻・更新・あなた・はじめの 3 ステップの旗・使い方）になり、タブは画面の下に固定される。幅が 400 px 以下のスマホでは、シートの名前を残すために読み込んだ時刻を隠し、緑の点だけを出す（時刻は更新の吹き出しに出る）。シートを開く・ログアウト・ライトとダークの切り替えは、スマホでは設定タブの「この端末」にある。アイコンは Material Symbols Rounded。

右上の「あなた」で自分の名前を選ぶと、自分の予定を書く列が決まり、卓の登録者としても記録される。選択はブラウザが覚える。未選択のあいだは枠が水色になる。自分の名前が要るボタン（参加希望・予定の印・日程調整の回答など）を押すと、吹き出しで知らせて、この欄にフォーカスが移る。

右上の月（ダークのときは太陽）のボタンでライトとダークを切り替えられる。設定タブの「見た目」では、端末の設定に合わせる状態にも戻せる。切り替わるのは押した人のブラウザだけで、ほかの人には影響しない。何も選んでいなければ OS の設定に従う。

配色は、黒い帯（上のバーとスマホの下のタブ）に水色を差し色にしたもの。主なボタンはライトでは黒、ダークでは白。状態の色は寒色でそろえ、全員空きはミント、× はローズ、メモと募集は薄紫。文字と背景の組み合わせは、どれも読みやすさの目安（コントラスト比 4.5）を超える。

使い方のページは、ウェブアプリの URL の後ろに `?page=tutorial` を付けると開く。入口は、タブの並びの続き（設定の隣）にある「使い方」。スマホでは上のバーに同じ「使い方」がある。ほかに、設定タブの「この端末」にある「使い方を見る」と、ログインの窓の「はじめて使う人は、使い方のページへ」からも開ける。どれも新しいタブで開く。卓のデータを持たないページなので、合言葉は求めない。はじめての人に向けて、次の章を載せている。予定表・参加希望・日程調整・卓の登録は、ページの上で押して試せる（試した結果はどこにも書かない）。アプリから開く使い方のページは、冒頭に見出しと始め方だけを置き、例の予定表は「予定を入れる」の章で試せる。共有用に公開したリンク（claude.ai）は、冒頭に例の予定表を置いた前の版のまま残している。

- 始め方の 3 ステップ（GM 向け。メンバーの登録 → Discord の登録 → 予定の登録）。合言葉は最初に開いたときに画面が聞くので、ステップには入れていない
- みんな向け: 予定を入れる、カレンダーを読む、卓に参加する、日程調整に答える、最新の状態にする
- GM 向け: 卓を登録する（状態の流れつき）、日程を決める、Discord に知らせる
- よくある質問

開いてからデータが届くまでは、カレンダーの形をした灰色の骨組みが出る。読み込めなかったときは理由と「もう一度読み込む」のボタンが出る。

卓の削除・ログアウト・一括変更・日程調整をやめる・Discord への案内・合言葉の変更などは、押すと確かめる窓が出る。ブラウザの確認ダイアログ（Apps Script では見慣れないドメイン名が付く）ではなく、画面の中の窓で聞く。消す・止めるといった戻しにくい操作では進むボタンが赤く、最初のフォーカスは「やめる」にある。Esc か窓の外を押すとやめる。

- カレンダー。左 7 割がカレンダー、右 3 割が「卓予定」と「選んだ日の内訳」。左右の矢印のボタンで月を送る。スマホではカレンダーを左右になぞっても送れる。「都合を見る卓」で卓を選ぶと、参加者の誰も △× を付けていない日（全員空き）が緑、× は無いが △ の人がいる日が薄い緑になる。
  - 上の段は、左に月送り（左右の矢印と「今月」）、右に「都合を見る卓」。その下の段に、一回り大きい「卓を登録」「募集を始める」「日程調整を始める」が並ぶ。カレンダーで日を選んでいると、ボタンが「10/9 に卓を登録」のようにその日の名前になり、押すとその日を開催日に入れた登録の窓が開く。日を選んでいなければ「卓を登録」のままで、開催日は空の窓が開く。「募集を始める」「日程調整を始める」は、状態が「募集」か「調整中」の登録の窓を開く（日付は持たない）。スマホでは月送り・都合を見る卓・募集と日程調整のボタンの 3 段になり、「卓を登録」は右下（下のタブの上）に浮かぶ大きなボタンになる。
  - 右の上が「選んだ日の内訳」、その下が「卓予定」。
  - 「卓予定」は、上から順に、募集中の卓（開きたい期間と参加希望の人数つき）、日程調整中の卓（候補の期間つき）、日程調整の回答待ち（候補日の数と未回答の人。自分が未回答なら「あなたの回答を待っています」と色付きで出る）、今日・明日・14 日以内の卓、候補の期間や開催日を過ぎた卓。募集中と調整中は見落としやすいので先に出し、薄紫の地に色を付ける。押すと「募集・調整」タブへ移る。明日の卓には開催前の知らせの状態（送信済み・「9/20（日） 20 時台に送る」・未送信・未設定）が添えられる。Discord と自動通知の設定の状態はここには出さない（設定タブで見る）。タップするとその日がカレンダーで選ばれる。募集中の行は「募集・調整」タブが開く。調整中の行は「都合を見る卓」がその卓になり、候補の期間の日に水色の枠が付く。
  - 卓の札には状態のアイコンが付く（開催・募集・終了・中止）。今日の卓だけは別のアイコンと緑の線が付く。終了と中止は灰色になり、その日のマスも灰色になる。募集中の卓は開催日を持たないのでカレンダーには出ない（古い版で仮の日を入れていた卓だけ出る）。
  - 調整中の卓は名前を出さず、アイコンだけが出る。候補の期間の日それぞれに調整期間のアイコン、日程調整中なら候補日にだけ候補日のアイコン（水色）。マウスを載せると卓の名前が出て、候補日なら ◯ の人数も出る。
  - 色の凡例（全員空き・△あり・卓あり・終わった卓・今日）の下の行で、「日をタップすると内訳が出ます」の右に、アイコンの凡例（開催・今日・募集・調整期間・候補日・終了・中止・メモ）が並ぶ。スマホではアイコンの凡例が次の行に折れる。
  - 日のマスはボタンなので、Tab で移って Enter でも選べる。読み上げでは「9月18日（金）、今日、卓 1 件、全員空き」のように、日付と中身の要約を読む。
  - 幅の狭い画面（900 px 以下）では、内訳はカレンダーのすぐ下（卓予定の上）に出る。日を選ぶまでは出ない。画面の下のほうの日をタップして内訳が隠れているときは、内訳が見える位置まで送る。
  - 右下「内訳」は、選んだ日の卓ごとに時間・GM・参加者・場所・メモ。候補の期間にその日が入る調整中の卓も「候補日」として並ぶ。日程調整の候補日なら ◯ の人数と「回答する」が出て、まだ日程調整をしていない調整中の卓には「日程を調整する」が出る。「Discord に通知」でその卓の案内をいま送る（今日がその卓の開催前の知らせの日なら開催前の知らせ済みになる。終了と中止の卓には出ない）。「編集」で変更の窓が開く。「続きを登録」で翌日の卓を、設定を引き継いだ登録の窓が開く。内訳の下の「この日に卓を登録」でも、その日を入れた登録の窓が開く。
  - 内訳の「この日に卓を登録」の隣に「この日に続きを登録…」の選択が出る（シリーズが 1 つでもあるとき）。シリーズを選ぶと、その日を開催日にして、直前の回の GM・参加者・時間・場所・メモを引き継いだ登録画面になる。
  - 内訳のいちばん下が、その日のメモ。卓と関係のない予定（合宿、イベント、忙しい週）を書いておくと、カレンダーのマスに 📝 付きで出る。「あなた」で選んだ名前と日時が残る。空にして保存すると消える。
- はじめの 3 ステップ。メンバーが 1 人もいないか、動いている卓が 1 つも無いあいだは、カレンダーの上に「1 メンバーを登録する → 2 Discord を登録する → 3 予定を登録する」の案内が出る。ボタンからそれぞれの画面へ移れる（Discord は設定タブの Webhook URL の欄）。Discord は使わないなら飛ばせる。メンバーと卓がそろうと消える。上の「使い方」の隣の「はじめの 3 ステップ」（スマホは上の帯にある旗のボタン）は押すたびに出す・閉じるが切り替わり、出しているあいだはボタンが押してある見た目になる。そろったあとでもカレンダーの上にもう一度出せて、閉じるまで出たままになる（読み込み直しても消えない）。ほかのタブで押したときは、閉じずにカレンダーへ移って見せる。済んだステップにも「開く」ボタンが付き、右上の × でも閉じられる。そろう前に閉じた場合は、画面を開き直すまで出ない。
- 募集・調整。カードには「次にすること」が水色の帯で出る。募集の卓は GM にだけ「集まったら「編集」で状態を「開催」か「調整中」に」、候補日をまだ出していない調整中の卓には「次は「日程を調整する」で候補日を選び、参加者に聞きます」（参加者がいなければ、先に参加者を入れる案内）。上に「募集中」、下に「日程調整中」の卓が、期間の始まりが早い順にカードで並ぶ。タブの名前の横に、両方を足した件数が出る。「募集中」「日程調整中」の見出しの右に「募集を始める」「日程調整を始める」のボタンが常にあり、卓が並んでいてもその場で新しく始められる（カレンダーの「卓を登録」の隣にあるものと同じ）。1 件も無いときは、空の欄にも同じボタンが出る。「募集中」「日程調整中」の見出しの横の「？」にマウスを載せる（スマホは押す）と、それぞれの説明が出る。
  - 日程調整中のカードには、候補の期間（「10/1（木）〜10/15（木） のどこか」）・GM・参加者・場所・メモが出る。「候補日をカレンダーで見る」を押すと、カレンダーに移って「都合を見る卓」がその卓になり、候補の日に枠が付く。参加希望・興味ありのボタンは無い（参加者はもう決まっているため）。
  - 「日程を調整する」を押すと、候補日を選ぶ窓が開く。候補の期間の日（期間が無ければ予定表の日数ぶん）が並び、各日の右に GM と参加者の「メンバーの予定」（全員空き、△ の人、× の人、卓ありの人）が出る。「全員空きの日だけ」で絞れる。期間の外の日は下の欄から足せる。開始と終了の時刻も入れる。「Discord で知らせる」を付けたまま「この候補日で聞く」を押すと、GM と参加者を呼んで候補日と答え方を Discord に流す。参加者のいない卓では始められない。
  - 始めると、カードに候補日ごとの行が出る。行には ◯ の人数（「◯ 1/3」）と、◯ の人・× の人・未回答の人が並ぶ。GM と参加者は自分の行の ◯ か × を押す。同じ印をもう一度押すと取り消す。候補日を出した人が GM か参加者なら、その人の ◯ は最初から付いている。GM・参加者でない人にはボタンが出ない。
  - 見出しの右に「どの日でもいい」がある。押すと、これからの候補日すべてに自分の ◯ が付く。どの日でも都合がつく人が、1 日ずつ押さずに済ませるためのもの。× を付けていた日があるときは、◯ に変わってよいかを先に聞く。付けたあとはボタンが緑になり、もう一度押すと（確かめてから）自分の回答だけを全部取り消す。ほかの人の回答は動かない。過ぎた候補日には付けない。これで全員の ◯ がそろえば、その場で開催日が決まる。
  - 開催日は自動では決めない。全員がこれからの候補日すべてに答えた時点で、GM だけをメンションした「📝 回答がそろいました」を Discord に送る（候補日ごとの ◯ の数つき。回答を受けたサーバーがその場で 1 回だけ送る。そろったあとに答えを変えても送り直さない）。
  - GM は候補日の行の「この日に決める」で開催日を選ぶ（全員が ◯ の日はボタンが強調される）。選べるのは GM と管理者だけ（GM が未定の卓は管理者）。決めると状態は「開催」になり、候補日と回答は片付き、Discord に「日程が決まりました」と流す（Webhook があるとき）。
  - 途中で「候補日を選び直す」と、外した日の回答だけ消え、残した日の回答は残る。「調整をやめる」で候補日と回答を消す（卓は調整中のまま）。
  - 以下は募集中のカード。カードには期間・GM・参加者・参加希望の人・興味ありの人・場所・メモが出る。
  - 「あなた」で自分を選んでから「参加希望」か「興味あり」を押す。片方だけ付き、もう一度押し直せば切り替わり、「取り消す」で外れる。押した瞬間に画面が変わり、シートに書かれる。Discord には流れない。
  - すでにその卓の GM か参加者なら、ボタンの代わりに「あなたはこの卓の参加者です」と出る。
  - 卓の状態が「調整中」か「開催」になると、参加希望の人はそのまま参加者に入る。興味ありの人は動かないので、入れるなら GM が参加者に足す。
  - 「編集」で変更の窓が開く。
  - 「興味ありの人に聞く」（GM 向け）。押すと一言を添える窓が開き（任意、500 文字まで）、興味ありの人にメンションした確認文を Discord に送る。一言は「💬 一言（名前）」として文に挟まる。Discord ID の無い人は名前で書く。文にはウェブアプリの URL が付き、開いて「募集・調整」タブの「参加希望」を押せば返事になる。送るとカードに「確認文を送りました（日時）」が残り、状態が「開催」になると消える。Discord の中のボタンは Webhook では付けられないので、返事はウェブアプリ側で受ける。
- メンバーの予定。日付ごとの予定表。空欄は「参加できる」扱いで、都合の悪い日にだけ △（調整すれば可）か ×（不可）を入れる。○ は無い。旧い版で入れた ○ は空欄と同じに読み、次に表示を作り直すと空欄になる。見出しと「絞り込み」「まとめて入れる」「卓をまとめて変える」「卓の多い人を左に」の横に「？」があり、マウスを載せる（スマホは押す）と、その項目の説明が出る。印とメモの付け方は見出しの「？」にある。
  - 表の上に、日の決まっていない卓（募集中・調整中）の帯が出る。名前を押すと絞り込みの「卓」がその卓になり、もう一度押すと戻る。
  - 絞り込みに「卓」がある。卓を選んだ時点で、その卓の GM と参加者（募集なら参加希望も）の列だけになる。「（なし）」で全員に戻る。隣の「どれかの卓に入っている人だけ」は卓の種類を問わず、募集・調整中・開催のどれかに入っている人だけを残す（2 つは重ねられる）。この 2 つは「あなた」ごとに、この端末が覚える（別の人を選ぶと、その人の設定に切り替わる）。「解除」で両方とも戻る。
  - 表はブラウザの幅に合わせて広がる。人が少なければ列が広がり、多ければ今までどおり横に送る。幅の狭いスマホでは「その日の卓」の列を細くする。
  - 「その日の卓」の列は、卓の名前を 1 行目に、祝日の名前を 2 行目に小さく出す。長い名前は途中で切らずに折り返し、行の高さが伸びる。
  - 名前の下に「GM 1・PL 3」のように、いま動いている卓（募集・調整中・開催）で GM をしている数と参加している数が出る。
  - メンバーの列は、稼働中の卓に入っている人ほど左に並ぶ。卓の数が多い順、同数なら GM の多い順、それも同じならメンバーの登録順。上下 2 つの表で並びは揃う。終わった卓と中止の卓は数に入らない。「卓の多い人を左に」を外すと登録順に戻り、その選択はブラウザが覚える。
  - 「卓をまとめて変える」を押すと、卓の一覧（卓の名前・シリーズ・状態・開催日・GM・参加者）が開く。行をタップするかチェックで選び、下の欄でまとめて変える（次項）。「編集」で変更の窓が開く。「終了・中止も表示」で終わった卓も出せる。開催日の欄には、募集中なら開きたい期間、調整中なら候補の期間が出る。
  - 下の予定表の「その日の卓」には、候補の期間にその日が入る調整中の卓が「調整: 卓名」、日程調整の候補日なら「候補: 卓名」と薄く出る。この期間の都合を入れておくと、GM が日を決めやすい。
  - 自分の列のマスをタップすると 空 → △ → × → 空 の順に変わり、その場でシートに書き込まれる。その日の卓に入っている人のマスは「参」（GM は「GM」）が自動で付き、タップしても変わらない。シート側のタブ名は「都合」のまま。
  - 自分の列のマスの右上にある鉛筆のボタンを押すと、その日のメモを書く窓が開く。「21 時から」「午前だけ」「少し遅れます」のような一言を 200 文字まで。保存するとマスの左上に水色の点が付く。マウスを載せると文が吹き出しで出て、タップでも出る。ほかの人のマスも同じ。印（△×）とは独立していて、印を変えてもメモは残り、「参」「GM」の日にも書ける。窓の「消す」で消える。カレンダーの内訳の「メンバーの予定」でも名前に点が付き、同じように出る。
  - 表の上の「絞り込み」を押すと、見せるメンバー・期間・曜日・条件（卓のある日／ない日、表示中の全員が空いている日、表示中の誰も × を付けていない日、土日祝）を絞る欄が開く。「自分だけ」で自分の列だけになる。普段は畳まれていて、絞り込み中は見出し行に「絞り込み中: N 日」と出る。開閉はブラウザが覚える。
  - 「まとめて入れる」を押すと開く欄で、印（△・×・空欄に戻す）・期間・曜日を選び、「自分の列に入れる」で一度に入れる。「平日」「土日」「全曜日」で曜日をまとめて選べる。「入力済みは残す」を付けると空欄だけに入り、外すと上書きする。卓に入っている日はどちらでも飛ばす。
  - 土曜は青、日曜と祝日は赤。祝日には「祝」の印と名前が付く（振替休日・国民の休日を含む。春分・秋分は計算式なので 2099 年まで）。土曜の下に灰色の線が入り、週の切れ目が分かる。
  - 表は画面の高さに収まる枠の中でスクロールし、見出し行と日付・曜・その日の卓の列は固定。マウスで表をつかんで動かすと横にも縦にもスクロールできる。
- 卓の登録・変更の窓。タブは無く、カレンダーの「卓を登録」「募集を始める」「日程調整を始める」、内訳の「この日に卓を登録」「この日に続きを登録…」「編集」「続きを登録」、「募集・調整」タブの「編集」、「卓をまとめて変える」の「編集」から開く。題は新規なら「卓を登録」、既存の卓なら「卓を変更」。開催日（募集なら開きたい期間、調整中なら候補の期間）は、卓の名前と状態のすぐ下にある。「閉じる」か Esc で閉じる。PC では画面の中央に、スマホでは下から出るシートとして開く。どの窓も、開いているあいだは後ろの画面を触れず、スクロールもしない。閉じるとフォーカスは開いたボタンに戻る。
  - 状態の下に、その状態の手順が 3 段で出る。「開催」は 日と時間 → GM と参加者 → Discord に知らせて登録、「募集」は 開きたい期間を入れて登録 → 参加希望と興味ありを待つ → 集まったら状態を変える、「調整中」は 参加者と候補の期間 → 候補日を選んで聞く → 全員が答えたら GM が日を選ぶ。「終了」「中止」は一言だけ。いまどの段かは水色の「いまここ」で示す。新しい卓と、状態を切り替えたところは 1 段目。今のままの状態なら、参加希望が付いているか、候補日を出したかで 2 段目か 3 段目になる。
  - 状態が「調整中」で、まだ候補日を出していない卓は、保存のボタンが「登録して候補日を選ぶ」（既存の卓なら「更新して候補日を選ぶ」）になり、保存したあと候補日を選ぶ窓がそのまま開く。参加者がいない卓では、窓の代わりに「先に参加者を入れてください」と吹き出しが出る。
  - 「登録」「更新」「この卓を削除」を押すと、窓はその場で閉じ、カレンダーには仮に出る（消える）。結果と Discord の送信の進み具合は、画面下の吹き出しに出る。サーバーが断ったとき（開催日の形式が読めないなど）は、入力を残したまま窓が開き直り、理由が出る。
  - 窓の上の「編集する卓」で既存の卓を選び直すこともできる。一覧に出るのは募集・調整中・開催・中止で、終了した卓は出ない。ほかの画面から「編集」で開いたときだけ、その 1 件が一覧に加わる（「新規に戻す」で消える）。「Discord に知らせる」を付けると、その場で Discord に流れる。
  - 「シリーズ」は、何日かに分けて開く卓を束ねる名前。1 日で終わる卓には要らない。候補に既にあるシリーズが出て、選ぶと直前の回（日付のいちばん新しい回）から GM・参加者・時間・場所・メモを引き継ぎ、名前が「シリーズ名 #3」のように次の番号になる。引き継いだあとは自由に直せる。既存の卓を開いたときは引き継がない。
  - シリーズ名を入れると、隣に「シリーズの最終日」の欄が出る。この日を過ぎたシリーズは、登録画面の候補から消える。最終日が空でも、いちばん新しい回から 180 日たてば消える（日付未定の回があるうちは残る）。何年も続けたときに、古いシリーズが候補に溜まらないようにするため。
  - 単発の卓から「続きを登録」を押すと、前の回と合わせて 1 つのシリーズになる。シリーズ名は元の卓の名前から末尾の数字を外したもので、前の回にも同じ名前が入る。
  - 開催日を入れると、その日に重なりがないかを見て注意を出す。同じ日に別の卓へ入っている人、その日に × や △ を付けている人が並ぶ。登録は止めないので、確かめてから保存する。
  - 状態が「募集」のときは、参加者の欄を出さない（これから集めるため）。
  - 新規で状態が「開催」のときは、開催日の下の「日を足す」で日を何個も並べられる。登録を押すと日付順に 1 回ずつ登録され、名前は末尾の数字を進める（「#1」→「#2」→「#3」。数字が無ければ「名前 #1」「名前 #2」）。GM・参加者・時間・場所・メモ・シリーズは全部同じ。重なる日は 1 つにする。「Discord に知らせる」を付けると、一括変更と同じ形で 1 通にまとめて流れる。
  - 状態は 募集 → 調整中 → 開催 → 終了 と進み、中止は別。新規登録の初期値は「開催」。「募集」を選ぶと開催日と時刻の欄が消え、代わりに「開きたい期間」の始まりと終わりを入れる。「調整中」を選ぶと同じ欄が「候補の期間」になる（どちらも「10/3〜10/17」の形。空なら期間未定、片方だけは断る、逆なら直す）。「開催」には開催日が要る。募集の卓を調整中か開催にすると、参加希望の人が参加者に加わる。
  - 募集のカードの「開催にする」を押すと、状態を「開催」にした窓がそのまま開く（開催日の欄にカーソルが入る）。
  - 募集から「開催」か「調整中」へ移すとき、興味ありの人がいれば、保存の前に確かめる窓が出る。参加者にする人だけチェックし、チェックしない人は一覧から外す（参加希望の人は今までどおり自動で参加者に入る）。「全員を参加者に」「全員を取り下げ」でまとめて選べる。
  - 募集中の卓を開くと、参加希望と興味ありの人が薄紫の欄に出る。状態を「開催」に変えると「保存すると参加希望の人が参加者に加わります」と案内が出て、保存した時点で参加者に入る（押した瞬間の仮表示でも入る）。その卓は「募集・調整」タブの募集中から消える。
  - 何日か続けて開く卓は、既存の卓を開いた窓の「続けて登録（翌日・設定を引き継ぐ）」を押す。GM・参加者・時間・場所・メモを引き継ぎ、開催日を翌日、名前の末尾の数字を 1 つ進めた（「#1」→「#2」）新規登録の形になる。数字が無ければ「（続き）」が付く。名前と日を確かめて登録する。
- メンバー。上が登録フォーム、下が一覧。名前・Discord ユーザーID・備考の追加と編集、削除。名前を変えると、卓の GM・参加者と都合表の見出しも追随する。削除しても卓に書かれた名前は残り、メンバーの予定タブの上に「メンバーに無い参加者」として出る。
- 設定。左に 5 つの区分（知らせ・この卓予定・この端末・入り口と合言葉・送信の記録）が並び、選んだ区分の中身だけが右に出る。狭い画面では区分が横に並ぶ。前に見ていた区分を覚えていて、次に開いたときはそこから出る。値は「設定」シートに書かれるので、シート側と同じものを見ている（合言葉と「この端末」だけはシートに出ない）。
  - 知らせ。1 枚の表で、行が知らせの種類、列が送り先・いつ・送るかどうか。行は 開催前の知らせ／期間前の催促／開始直前の知らせ／登録・変更・削除／募集と参加確認 の 5 つ。日数・時刻・分の欄は表の中にあり、欄を離れると保存する。いちばん右のつまみで ON / OFF を切り替える（開催前の知らせは、ON にするとき確かめる窓が出る）。表の下に「例: 10/3（土）の卓なら、10/2（金）の 20 時台に届きます。」と出る。まだ送っていないときは、その後ろに「いまは送っていません」と添える。
  - 送り先は表に URL を出さず、下の折りたたみで決める。「チャンネル（Discord の Webhook URL）」に基本のチャンネルと種類ごとのチャンネル、「シリーズごとの上書き」にシリーズごとの設定が入る。どちらも畳んだ状態で開き、見出しの右にいまの状態（「基本・開催前」「2 件」など）が出る。
  - この卓予定。卓予定の名前（画面の左上とスプレッドシートの名前。80 文字まで。変える前に確かめる）、開催日を過ぎた卓を「終了」に自動で変えるかどうか、シートのカレンダーの表示月数、メンバーの予定の日数。
  - この端末。このブラウザだけの設定で、シートには書かない。自動更新の間隔、見た目（端末の設定に合わせる・ライト・ダーク）、文字サイズ（小・中・大。小がもとの大きさで、中は 1.12 倍、大は 1.25 倍に画面全体を拡げる）、使い方を見る、シートを開く、ログアウト。
  - 入り口と合言葉は合言葉の変更、送信の記録は新しい順 10 件の送信記録。
  - 管理者。いまの状態（「まだ決まっていません」「あなたは管理者です」「あなたは管理者ではありません」）、名簿、管理者の合言葉を決める・変える。名簿の名前の × で外せる（管理者が 1 人だけのときは外せない）。
  - Discord の欄は「基本のチャンネル」。種類ごとのチャンネルやシリーズ専用のチャンネルを決めていない知らせと、一括変更の知らせはここへ送る。
  - 種類ごとのチャンネル。「開催前の知らせ」と「募集」の 2 つに、それぞれ Webhook URL を貼って「URL を保存」する。いまの URL は伏せて出し、決めていなければ「（基本のチャンネルと同じ）」と出る。「接続テスト」はそのチャンネルだけに送る。「外して基本に戻す」で空にすると、その種類は基本のチャンネルへ戻る。開催前の知らせは、開催前に自動で送る知らせと、シートのメニューの「明日の卓を今すぐ Discord に送る」。募集は、状態が「募集」の卓の登録・変更・削除・案内と、「興味ありの人に聞く」。日程調整（候補日の知らせと日程決定）は基本のまま。
  - Webhook URL を貼る欄の横にある「？」を押すと、Webhook URL の取り方（チャンネルの編集 → 連携サービス → ウェブフック → 新しいウェブフック → URL をコピー、スマホでの開き方、権限が無いとき、URL の扱い）が画面の中央に出る。Esc か ×、外側を押すと閉じる。
  - 開催前の知らせの欄は、有効なら「有効」とだけ出る。日時は「開催日の [1] 日前、[20] 時台に送る」の 2 つの欄で入れる（0 日前は当日、1 日前は前日。何日前は 0〜30、時刻は 0〜23）。下に「例: 9/26（土）の卓なら、9/25（金）の 20 時台に届きます」と例えが出て、範囲の外なら理由が赤で出る。有効になる前のボタンは「有効にする」、有効になったあとは「この日時で保存」（日時だけを書き換え、見回りのトリガーは作り直さない）。
  - シリーズごとの通知。シリーズを選び、専用の Webhook URL、「基本のチャンネルにも送る」、開催前の知らせの日時（「開催前の知らせは基本と同じ日時」を外すと「開催日の [ ] 日前、[ ] 時台」の欄が出る）を決めて「保存」を押す。URL は変えるときだけ貼る。決めたシリーズは上に一覧で出て、行を押すとそのシリーズを選べる。「接続テスト」はそのシリーズのチャンネルだけに送る。「設定を消す」で基本のチャンネルと基本の日時に戻る。選べるのは、終わっていないシリーズと、設定が残っているシリーズ。
  - 卓の登録の窓の「Discord に知らせる」は、シリーズの欄に合わせて変わる。基本の URL が無くても、専用の URL があるシリーズなら付けられ、横に「（シリーズのチャンネルへ）」のように送り先が出る。
  - 合言葉を変えるには、いまの合言葉と新しい合言葉（8 文字以上、2 回）を入れる。変えた本人のブラウザはそのまま使え、ほかの人は次に開いたときに新しい合言葉を求められる。開いたままの人も、次に何か書こうとした時点で求められる。

#### 一括変更（メンバーの予定タブの「卓をまとめて変える」）

チェックで選んだ卓に、次のどれかをまとめて当てる。「過ぎた卓を選ぶ」で、開催日を過ぎたまま稼働中の卓だけを選べる。

| 操作 | 内容 |
|---|---|
| 状態を変更 | 募集 / 調整中 / 開催 / 終了 / 中止 のどれかに。開催日の無い卓は「開催」にできない。募集中の卓を「調整中」「開催」にすると、参加希望の人が参加者に入る。募集でも調整中でもなくなると期間は消える |
| 参加者を追加 | 選んだメンバーを参加者に足す。すでにいれば重複しない |
| 参加者から外す | 選んだメンバーを参加者から消す。GM は変えない |
| GM を変更 | 選んだメンバーを GM にする |
| 開催日をずらす | 7 や -1 のように日数を入れる。開催前の知らせと開始直前の知らせの印は消えるので、ずらした先で日が来ればまた送られる。開催日の無い卓は飛ばす |
| シリーズを変更 | 選んだ卓にシリーズ名を付ける。空のまま実行すると外す。ばらばらに登録した回をあとから束ねるときに使う |
| 削除 | 行ごと消す。戻せない |

「Discord に知らせる」を付けると、何をどの卓に当てたかを 1 通で流す。

#### 読み込みを軽くしている工夫

- 日付と時刻の組み立ては自前で行う。Apps Script の `Utilities.formatDate` と `Session.getScriptTimeZone` は外への呼び出しで、1 回の読み込みで何百回も呼ぶと目に見えて遅い。画面 1 回ぶんのシート操作は 397 回から 47 回に減った。
- 画面を開くと、この端末に控えた前回の内容をすぐ描く。最新のデータはその後ろで読み直し、違っていれば描き直す。待っているあいだも卓とカレンダーが見える。控えはログアウトや合言葉の変わったときに消える。
- 使い方のページの見出しに使う日本語フォントは、見出しに出てくる字だけを読み込む。フォントの合計は 35KB ほど。

#### 最新の状態にする（更新と自動更新）

データはシートから読む。ほかの人が書いた内容は、「更新」か自動更新で画面に入る。

- 右上の時刻は、いま見ているデータを読み込んだ時刻。左の点が緑なら自動更新が有効、灰色なら自動更新しない、赤なら自動更新で読み込めなかった（通信を確かめる）。マウスを載せると日時と間隔が出る。
- 「更新」を押すと、アイコンが回ってボタンが押せなくなる。読み終わると吹き出しに「最新の状態にしました（22:10 時点）」か「最新の状態です。変更はありません（22:10 時点）」と出る。
- 自動更新は、画面を開いているあいだ決まった間隔（既定は 3 分）で読む。中身が変わっていたときだけ描き直し、吹き出しに「ほかの人の変更を反映しました」と出る。変わっていなければ時刻だけが進む。
- 窓を開いている、文字を入力している、予定表をドラッグしている、自分の書き込みの返事を待っている、画面が隠れている（別のタブや別のアプリを見ている）。このどれかのあいだは読まず、15 秒おきの確認で改めて読む。
- 別のタブやアプリから戻ったときは、前の読み込みから 1 分以上経っていればすぐ読む。
- 間隔は設定タブの「この端末」で、しない・1 分・3 分・5 分・10 分から選ぶ。このブラウザだけの設定。
- 読み直しても書きかけは消えない。日付メモの書きかけ、メンバーの登録フォームの入力、設定タブの時刻・表示月数・日数の入力は、保存するまで残る。
- 読んでいるあいだに自分が書き込みを始めたときは、その読み込みの結果では描かない（押した印が一瞬戻るのを防ぐ）。書き込みの返事のあとで読み直す。


自分の操作は押した瞬間に画面へ仮に出て、サーバーの返事で確定する。返事には最新のデータが同梱されるので、登録のあとに読み直す往復は無い。
ウェブアプリからの書き込みは、データの行だけを書く。シート側の 4 枚（カレンダー・一覧・管理・都合）の描き直しはその場ではせず「あとで」の印を付け、10 分おきのトリガーとシートを開いたときに描き直す。この描き直しは 1 回で 300 回ほどシートを操作する重い処理なので、登録のたびにやると十数秒待たされる。

### 卓の状態と、当日・終わった卓の扱い

状態は 5 つ。募集 → 調整中 → 開催 → 終了 と進み、中止は別。旧い版にあった「予定」は「開催」にまとめた（開催日が決まっている、という意味）。

| 状態 | 意味 | 開催日 |
|---|---|---|
| 募集 | 参加者を集めている。「募集・調整」タブに並び、参加希望・興味ありを付けられる | 持たない。代わりに開きたい期間（「10/3〜10/17」） |
| 調整中 | 参加者は決まり、開催日を選んでいる。募集のときの参加希望の人は、このときに参加者へ移る。「日程を調整する」で全員が答えたら、GM が選んだ日で「開催」になる | 持たない。代わりに候補の期間（「10/3〜10/17 のどこか」） |
| 開催 | 開催日の当日。自動で変わる | 必須 |
| 終了 | 開催日が過ぎた。自動で変わる | あってもなくてもよい |
| 中止 | 取りやめ | あってもなくてもよい |

開催日を過ぎた「開催」の卓は、次に画面を開いたときか表示を作り直したときに「終了」へ変わる。当日はそのまま「開催」で残る。手で状態を選び直す必要はない。

- カレンダーからは消えない。「済」を頭に付けた灰色の札として残り、その日のマスも灰色になる。中止の卓も同じように残る（「中止」を頭に付け、ウェブアプリでは取り消し線が付く）。
- 一覧と「卓予定」の欄からは消える。「卓をまとめて変える」の一覧で見るには「終了・中止も表示」を付ける。
- 「募集」「調整中」の卓は触らない。候補の期間を過ぎた調整中の卓は「卓予定」の欄で知らせるだけで、状態は変えない。
- 止めたいときは、設定タブの「開催日を過ぎた卓を『終了』にする」を外す。

### カレンダー（シート）

- 上 2 行は固定。左上の「都合を見る卓 ▶」の右のセルがドロップダウンで、「全員」「（なし）」と、いま動いている卓の名前から選べる。
- 選ぶと、その卓の GM と参加者の誰も「都合」に △× を付けていない日が緑（「◎ 全員空き」）、× は無いが △ の人がいる日が薄い緑（「△ あり」）になる。× の人や卓に入っている人がいる日は色が付かない。
- 「お知らせ」欄には、今日と明日の卓、7 日以内の卓、募集中の卓（開きたい期間と参加希望の人数）、日程調整中の卓（候補の期間、日程調整中なら「候補日 N 日・未回答 M 人」）、候補の期間や開催日を過ぎたままの卓、Discord と自動通知の設定状況が出る。
- 月の格子は、週ごとに「日付の行」と「中身の行」の 2 行。中身には「開始時刻 卓名／GM」が並ぶ。当日の卓には「開催」が付く。調整中の卓は候補の期間の日に「◇ 卓名（調整中）」、日程調整中なら候補日に「🗳 候補日: 卓名」が並ぶ。
- 「都合を見る卓」で募集中の卓を選ぶと、GM・参加者に参加希望の人を加えた全員で都合を判定する。

### 一覧（シート）

- 募集・調整中・開催の卓を、開催日の近い順に並べる。日付の無い卓は期間の始まりが早い順で後ろに、期間未定はその後。
- 「あと」列は今日・明日・N 日後。今日は赤、明日は橙、7 日以内は青。募集中の卓は「10/3（土）〜10/17（土） 募集中」、調整中の卓は「10/3（土）〜10/17（土） のどこか 調整中」のように出る。
- 「参加希望」「興味あり」の列に、募集中の卓に希望を出した人が並ぶ。「シリーズ」の列に、束ねている名前が出る。
- 開催日が過ぎた卓は翌日に自動で「終了」になり、この一覧からは消える。カレンダーには灰色で残る。
- 「開催前の知らせ」列に、Discord へ送った日時が残る。

### 管理（シート）

- 上に稼働中の卓数（募集・調整中と、開催の内訳）、今月と来月の開催数、GM の人数。
- 「卓 × メンバー」は卓が行、メンバーが列。GM のところに「GM」、参加者に「PL」。募集中の卓では参加希望の人に「希望」（黄）、興味ありの人に「興味」（灰）。列の下に、その人が参加している卓数と GM をしている卓数。
- 「メンバー別」は人ごとの参加卓の一覧。GM の卓には★。
- メンバーシートに無い名前が参加者に入っていると、上部に黄色の注意が出る。

### 日付メモ（シート）

ウェブアプリのカレンダーで書いたメモが入る。列は日付・メモ・書いた人・更新日時。ここに直接書いてもカレンダーに出る。

### 日程調整（シート）

「募集・調整」タブで付けた回答が入る。列は卓ID・日付・名前・回答（◯ か ×）・更新日時。1 行が 1 人の 1 候補日ぶん。回答を取り消すと行が消える。開催日が決まったとき、日程調整をやめたとき、卓を消したときに、その卓の行はまとめて消える。

### 予定メモ（シート）

ウェブアプリの「メンバーの予定」で書いた、マスごとのメモが入る。列は日付・名前・メモ・更新日時。1 行が 1 マス。ここに直接書いても、次の表示更新で都合シートのセルのメモに出る。メンバーの名前を変えると、ここの名前も追随する。

### 都合（シート）

- 行が日付（今日から 60 日分。設定で変えられる）、列がメンバー。空欄は参加できる扱いで、都合の悪い日だけ自分の列に △× を入れる。セルはドロップダウン（△・×・参・GM）。旧い版の ○ は空欄と同じに読み、表示を作り直すと空欄になる。
- 「その日の卓」列に、その日に入っている卓の名前が出るので、二重予約に気づける。候補の期間にその日が入る調整中の卓は「調整: 卓名」、日程調整の候補日なら「候補: 卓名」と出る。
- 「開催」の卓に入っている人のマスは「参」（GM は「GM」）が自動で入り、青くなる。手で書き換えても戻る。この人はその日、ほかの卓の都合判定では空いていない扱いになる。募集中の卓には付かない。
- 曜日の列は日曜と祝日が赤、土曜が青。祝日は「月祝」のように「祝」が付く。土曜の行の下に灰色の線が入る。カレンダーの日付も祝日は赤で、名前が添えられる。
- ウェブアプリで書いた予定メモは、そのマスのセルのメモ（右上の黒い三角）として出る。マウスを載せると読める。データ本体は「予定メモ」シートにある。
- 行は「表示を更新」のたびに今日から作り直されるが、入れた印は日付ごとに引き継がれる。

### セッション

卓のデータ本体。ウェブアプリを使わず直接直してもよい。列は ID・卓の名前・GM・参加者・開催日・開始・終了・状態・場所 / URL・メモ・登録者・更新日時・開催前の知らせ。その右に募集時期（旧）・参加希望・興味あり・参加確認・シリーズ・期間・候補日・シリーズ最終日・期間前の催促・開始直前の知らせが続く。古い版のシートには、次に表示を作り直したときに右の列が足される。「期間」は、募集中なら開きたい期間、調整中なら候補の期間で、「2026/10/03〜2026/10/17」の形（「~」区切りや逆順でも読める）。「募集時期（旧）」は前の版の「2026/10 前期」を入れていた列で、シートを整え直したときに「期間」（前期なら 1〜15 日、後期なら 16 日〜月末）へ移して空になる。「期間前の催促」「開始直前の知らせ」は送った日時で、自動で書かれる。空にすると、その日ならもう一度送る。「参加確認」は「興味ありの人に聞く」で Discord に送った日時で、自動で書かれる。「シリーズ」は何回かに分けて開く卓を束ねる名前で、同じ名前の行が 1 つのキャンペーンになる。「候補日」は日程調整の候補日で、「2026/10/03、2026/10/04」の形で自動で書かれる。開催日が決まると空になる。

- 参加者は「、」区切り。メンバーシートの名前に合わせる。
- 開催日が未定なら空欄にして、状態を「募集」か「調整中」にし、「期間」に開きたい期間を入れる。
- 状態は 募集 / 調整中 / 開催 / 終了 / 中止 の 5 つ。一覧に出るのは募集・調整中・開催。旧い版の「予定」は読み込み時に「開催」として扱い、シートの値も版を上げたときに書き換える。
- 「参加希望」「興味あり」は「、」区切りの名前。「募集・調整」タブの操作でここに書かれる。状態が「調整中」か「開催」になると参加希望の人は参加者の列へ移る。
- 「開催前の知らせ」を空にすると、開催前の知らせの日なら次の見回りでもう一度送る。旧い版の見出し「前日通知」は、版を上げたときに「開催前の知らせ」へ直る。

## 管理者

みんなの合言葉とは別に「管理者の合言葉」を 1 つ持つ。作りはみんなの合言葉と同じで、ハッシュと版をスクリプトのプロパティに置き、通ったブラウザには「管理者の証」を渡す。名簿（「設定」シートの「管理者」）は誰が管理者かを見せるためのもので、実際に通すかどうかは証で決める。

- **決めるまでは今までどおり。** 管理者の合言葉が無いあいだは、画面を開ける人なら誰でも管理者の操作ができる。既に使っている卓予定を新しい版にしても、締め出されない。
- **最初の管理者。** 最初の合言葉を決めた人が、そのとき「あなた」で選んでいた名前で名簿に載る。以後は、管理者の合言葉を通した人がその名前で名簿に加わる。
- **管理者だけの操作**: シートを開く（管理者でなければ、シートの URL をサーバーが渡さない）／ほかの人の都合・予定メモ・参加希望・日程調整の回答を代わりに入れる／メンバーの追加・変更・削除／設定の変更（知らせ・表示・卓予定の名前・シリーズごとの上書き）／みんなの合言葉の変更／卓をまとめて変える／卓の削除。自分のぶんの印や回答、卓の登録と変更は、今までどおり誰でもできる。
- **断られ方。** サーバーは「ADMIN:」で始まるエラーを返す。画面はそれを見て管理者の合言葉の窓を出し、合っていればその操作をやり直す（押し直さなくてよい）。
- **証の寿命。** ログアウトするか、管理者の合言葉を変えるまで有効。変えると、ほかの管理者は次の操作のときに入れ直しになる。
- **忘れたとき。** シートのメニュー「卓予定 → 管理者の合言葉を設定…」から決め直せる。空のまま OK を押すと管理者の合言葉をやめ、全員が操作できる状態に戻る。
- **守りの強さ。** 「あなた」の名前は自己申告なので、名簿は見せるためのもの。実際に止めているのは管理者の合言葉で、これを知らない人はシートの URL も受け取れない。

## 通知の仕組み

- 開催前の知らせ。ウェブアプリの「設定」タブか、シートのメニュー「卓予定 → 自動通知を設定」で有効にする。有効にすると `dailyNotify` が 1 時間ごとに見回る（「開始直前の知らせ」が ON のあいだは 5 分ごと。設定を切り替えるとトリガーも作り直す）。状態が「開催」で、今日が開催前の知らせの日（開催日の N 日前。N はシリーズの値か基本の値）の卓のうち、まだ送っていなくて、送る時刻（シリーズの時刻か基本の時刻）になった卓を集め、送り先と「あと何日」ごとに 1 通にまとめて Webhook へ送る。本文の頭は「📢 明日は卓の日です！」のように、今日・明日・あさって・N 日後で言い分ける。開催前の知らせの日を過ぎてから登録した卓（3 日前の設定で、明日の卓を今日登録したなど）は送らない。本文に参加者と GM のメンション、embed に卓ごとの GM・日時・参加者・場所・メモ。送れたら「開催前の知らせ」列に日時を書くので、次の見回りでは送り直さない。送り先が 2 か所ある卓は、どちらか 1 か所に届けば送った扱いにする。見回りで送るものが無かったときは、基本の時刻の回だけ「送らず: 理由」を通知ログに残す（同じ日の同じ時刻台では 1 回だけ。見回りの記録でログを埋めないため）。
- 期間前の催促。設定の「期間前の催促」が ON のとき、見回りのたびに、状態が募集中・調整中で期間の始まりが明日の卓を探す。送る時刻は開催前の知らせ（時刻）（シリーズで変えていればその時刻）。本文は「⏳ 明日から「卓名」の募集の期間です。まだ参加者を集めている途中です。」（調整中なら「候補の期間です。まだ開催日が決まっていません。」）で、GM をメンションし、卓予定の URL と卓の embed を添える。送り先は募集の卓なら募集のチャンネル、調整中なら基本のチャンネル（シリーズの設定があればそちらが優先）。送れたら「期間前の催促」列に日時を書き、期間を変えるまで送り直さない。
- 開始直前の知らせ。設定の「開始直前の知らせ」が ON のとき、見回りのたびに、今日の「開催」の卓で開始時刻が入っているものを探し、開始まで残り◯分以内（既定 30 分）になったら送る。本文は「⏰ あと 20 分で「卓名」が始まります。」（開始を過ぎていれば「まもなく…」）で、GM と参加者をメンションする。送り先は開催前の知らせのチャンネル。開始を 15 分以上過ぎた卓には送らない。送れたら「開始直前の知らせ」列に日時を書き、開催日か開始時刻を変えるまで送り直さない。ON のあいだは見回りが 5 分ごとになるので、指定した時刻を過ぎた最初の見回りで届く（最大 5 分ほど遅れる）。
- 手動送信。シートの「卓予定 → 明日の卓を今すぐ Discord に送る」は、開催前の知らせの日時にかかわらず、明日の卓をまとめて送り直す。ウェブアプリの「Discord に通知」は卓 1 件の案内を送り、今日がその卓の開催前の知らせの日なら開催前の知らせ済みの印を付ける（開催前の知らせの日がまだ先なら付けず、その日にあらためて送る）。
- 登録・変更・削除の通知。登録タブで「Discord に知らせる」を付けたときだけ送る。
- 卓予定の URL。募集・調整中の卓の登録・変更・案内には「🔗 参加希望は卓予定の「募集・調整」タブから: URL」（調整中なら「日程調整は…」）、日程が決まった知らせには「🔗 卓予定: URL」を添える。興味ありの人への参加確認と日程調整の候補日の知らせには、前から URL が付いている。開催の卓の知らせと削除の知らせには付けない。URL はウェブアプリの公開 URL で、取れないときは行ごと出さない。
- 送り先。卓のシリーズに専用の Webhook URL があればそのチャンネルへ、「基本のチャンネルにも送る」が ON なら基本のチャンネルへも送る。専用の URL が無ければ基本のチャンネルへ。ここでの「基本のチャンネル」は、開催前の知らせなら開催前の知らせのチャンネル、募集の知らせなら募集のチャンネル（どちらも決めていれば。決めていなければ基本の URL）。登録・変更・削除、案内、参加確認、日程調整、日程決定、開催前の知らせのすべてが、卓のシリーズで送り先を決める。同じシリーズの回をまとめて登録したときも、そのシリーズの送り先へ。「メンバーの予定」タブの一括変更と、基本の接続テストは基本のチャンネルへ。通知ログの「対象」には、専用のチャンネルへ送った行だけ「（シリーズ「名前」のチャンネル）」「（開催前の知らせのチャンネル）」「（募集のチャンネル）」が付く。
- 画面上。開いたときに今日と明日の卓を吹き出しで出す。カレンダーの「お知らせ」とウェブアプリの「卓予定」に、明日の卓の開催前の知らせの状態（送信済み・いつ送るか・未送信・未設定）を出す。ウェブアプリの内訳にも、まだ送っていない卓には「開催前の知らせ 9/27（日） 20 時台に送る」のように出る。
- 429（Cloudflare の 1015 を含む）と 5xx で失敗したときは、約 3 秒、約 8 秒と間を置いて最大 3 回まで送り直す。Discord が Retry-After を返せばそれに従う（上限 15 秒）。400 や 404 は送り直さない。1 回ごとに通知ログへ 1 行残り、2 回目以降は「（2 回目）」のように回数が付く。
- ウェブアプリからの送信は、サーバーに 1 回ずつ頼み、待ちと送り直しは画面側が行う。だから画面に「シートに保存しています…」「Discord に送信中…（1 回目／最大 3 回）」「Discord が混雑しています（HTTP 429）。8 秒後に 2 回目を送ります…」「Discord に送りました（2 回目で成功）」と、いま何をしているかが順に出る。卓の登録・削除、内訳の「Discord に通知」、一括変更、接続テストのすべてで同じ。送り先が 2 か所あるときは 1 か所ずつ順に送り、途中の表示に「［1/2 シリーズ「名前」のチャンネル］」のように送り先が付く。片方だけ届かなかったときは、届いた先と届かなかった先を分けて出す。開催前の知らせはトリガーが動かすので、待ちはサーバー側で行う。
- 送った結果は「通知ログ」シートに残る。ウェブアプリの設定タブにも新しい順 10 件が出る。日時は「2026/09/15（火） 21:23」の形。開催前の知らせの日時と日付メモの日時も同じ形で出る（シートが日付型に変えても英語表記にならない）。失敗したときは HTTP のコードと本文の先頭に、まず疑う場所の見当（URL の間違い・本文・承認不足など）が添えられる。何も送らなかったときも「送らず: 理由」と残るので、トリガーが走ったかどうかと、どの日を「明日」と見たかが分かる。
- 卓を登録したときの知らせは、GM と参加者をメンションする（複数日をまとめて登録したときも、その回の全員）。変更と削除の知らせはメンションしない。
- 参加者の Discord ユーザーID は無くても送れる。ID のある人だけメンションされ、無い人とメンバー未登録の人は名前で本文に載る。

### Discord に届かないときの確かめ方

失敗したときは、画面・吹き出し・通知ログのどれにも「送信失敗（種類）」と種類が先に出る。種類は次の 6 つ。ツールの不具合でないものには「このツールの不具合ではありません」と添える。

| 種類 | 何が起きたか | ツール側の問題か |
|---|---|---|
| Discord 側の制限 | Discord の手前の Cloudflare が混雑で受け取りを断った（HTTP 429、error code 1015） | いいえ。Google の共有サーバーから送る通知がまとめて数えられるため、こちらが 1 通でも起きる |
| Discord 側の不調 | Discord が応答できない（5xx） | いいえ |
| Webhook URL | URL が違う、または消された（401 / 403 / 404） | いいえ。設定の問題 |
| 本文 | Discord が本文を受け付けなかった（400） | 可能性あり。送信記録の詳細を添えて知らせる |
| 承認 | スクリプトの承認が足りない | いいえ。デプロイし直して承認を通す |
| 通信 | Discord に届く前に切れた | いいえ |

設定タブの「最近の送信記録」（または「通知ログ」シート）を上から見る。

| 記録 | 意味 | 直し方 |
|---|---|---|
| 記録が 1 行も無い | 送る処理まで届いていない | 開催前の知らせなら、設定タブの「開催前の知らせ」が有効か、今日がその卓の開催前の知らせの日か。登録時の通知なら「Discord に知らせる」が付いていたか |
| 送らず: 明日の卓なし | その日を「明日」と見て卓が無かった | 日付が 1 日ずれていれば、スプレッドシートと Apps Script のタイムゾーンを東京に揃える |
| 送らず: すべて送信済み | 一度送った卓は二度送らない | 送り直すなら卓の内訳の「Discord に通知」か、シートの「明日の卓を今すぐ Discord に送る」 |
| 送らず: Webhook URL が空 | URL が保存されていない | 設定タブに貼って「URL を保存」 |
| 送信失敗（Webhook URL）: HTTP 401 / 403 / 404 | URL が違う、または Discord 側でウェブフックが消された | Discord で作り直して貼り直し、「接続テスト」 |
| 送信失敗（本文）: HTTP 400 | 本文を受け付けなかった | 卓名やメモが極端に長くないか。直らなければツール側の問題かもしれない |
| 送信失敗（Discord 側の制限）: HTTP 429 error code: 1015 | Discord の手前の Cloudflare が混雑で弾いた。Apps Script の通信は Google の共有サーバーから出るので、こちらが 1 通でも起きる。ツールの不具合ではない | 3 回まで自動で送り直したうえでの失敗。数分おいて押し直す |
| ERROR … external_request / 承認 | スクリプトの承認が足りない | Apps Script の「デプロイを管理」で新バージョンを出し、承認画面を通す |

メンバータブで Discord ユーザーID に「⚠ 桁がおかしい」が出ている人は、メンションだけ効かない。ID は 17〜20 桁の数字で、シートのセルが数値の書式だと末尾の桁が丸まる。文字列として入れ直す。

## 複数人で使うときの決まりごと

- ウェブアプリは URL と合言葉を知っていれば使える。公開の設定は「全員」なので、Google のログインは求めない（2026-09-19 に「Google アカウントを持つ全員」から切り替えた）。見る人は Google アカウントを持っていなくてよい。シートのメニューは編集者なら誰でも使える。シート側の承認は各自が初回に一度だけ求められる。
- 合言葉は全員共通で 1 つ。誰かをグループから外したときは、設定タブで合言葉を変える。その人が覚えていた記憶は無効になり、新しい合言葉を知らなければ開けない。残る人には新しい合言葉を伝える。
- 合言葉を忘れたら、シートの編集者がメニュー「卓予定 → ウェブアプリの合言葉を設定…」で決め直す。この場合も全員が入れ直しになる。
- 合言葉はハッシュにしてスクリプトのプロパティに置く。シートには出ない。8 文字以上（2026-09-19 に 4 文字から引き上げた。前に決めた短い合言葉もそのまま使える）。10 回続けて間違えると 10 分ほど入れられなくなる。この待ちは全員で共通なので、誰かが間違え続けると新しく入る人も待たされる。一度入ったブラウザには影響しない。
- ウェブアプリは「自分として実行」なので、開いた人の操作はすべて公開した人の権限で書き込まれる。URL は卓の仲間の外に出さない。
- シート側の表の描き直し（10 分おき）のトリガーは、ウェブアプリを公開した人のアカウントで動く。止めたいときは Apps Script の「トリガー」画面で refreshIfDirty を消す。
- 自動通知のトリガーは、有効にした人のアカウントで動く。ウェブアプリの「設定」タブから有効にした場合は、誰が押しても公開した人のアカウントになる。シートのメニューから有効にした場合はその人のアカウントで、その人が編集権を失うと止まる。引き継ぐときは新しい人が有効にし直す。二人が設定しても、通知済みの印があるので二重には送らない。トリガーは 1 時間ごとの見回りが 1 本だけで、時刻を変えても作り直さない（時刻は「設定」シートと「シリーズ通知」シートから毎回読む）。旧い版の「毎日 1 回」のトリガーは、版を上げてシートを整え直したときに 1 度だけ見回りへ置き換わる。
- シートのメニューで設定した自動通知は、ウェブアプリからは解除できない（別アカウントのため）。設定した本人がシートのメニュー「自動通知を解除」で止める。画面にはその旨が出る。
- Webhook URL（基本・開催前の知らせ・募集）は「設定」シートに、シリーズの分は「シリーズ通知」シートに置くので、編集者全員に見える。ウェブアプリの画面では伏せて出す。URL を知っていれば誰でもそのチャンネルに投稿できるため、卓の仲間以外には共有しない。気になるなら「設定」シートを保護して、編集できる人を絞る。
- 予定は各自が自分の列に入れる。他人の列は触らない。
- 参加者はメンバーシートの名前で書く。表記が違うと別人扱いになり、都合の判定と管理表から漏れる。

## 制約と注意

- シート側で直接セッション・メンバー・都合・設定を編集したときは、その場で表示を作り直す。1〜3 秒かかる。ウェブアプリからの書き込みは作り直しをしないので速いが、シート側の表に映るのは最大 10 分後になる。
- 自動通知の時刻は「時台」で、Google 側がその 1 時間のどこかで実行する。19 時ちょうどには来ない。
- Discord の 1 メッセージに載る embed は 10 件まで。明日の卓が 11 件以上あれば 11 件目からは載らない。
- スクリプトとスプレッドシートのタイムゾーンが揃っていないと、日付が 1 日ずれる。導入手順の 2 と 6 で両方を東京にする。
- 開催日を過ぎた「開催」の卓は、画面を開いたときや表示を作り直したときに「終了」へ変わる（設定の「過ぎた卓を自動で終了」が ON のとき）。中止にしたいときは、その前に状態を「中止」にしておく。
- 参加希望と興味ありは通知を出さない。募集の締め切りを知らせたいときは、カレンダーの内訳か募集の卓の案内を「Discord に通知」で送る。案内には期間と参加希望の人が載る。期間の始まる前日には、GM に催促が自動で届く。
- 承認画面の「このアプリは Google で確認されていません」は、自分で作ったスクリプトには必ず出る。「詳細」から進む。
- ウェブアプリはコードを貼り直しただけでは変わらない。「デプロイを管理」から新バージョンを出す。
- 新しい版を貼ったあと、シートの列や「状態」のドロップダウンは、シートを開いたときか、ウェブアプリからの最初の書き込みで整え直される（版を控えていて、違うときだけ）。その 1 回だけ数秒多くかかる。
- 同時に押されても、書き込みは 1 件ずつ順に処理する（2 つ下の項）。
- サーバーへの呼び出しには 45 秒の時間切れがある。返事が返ってこないと、書き込みのあいだ押せなくしたボタン（卓の窓の「登録」「この卓を削除」、メンバーや設定のボタン）がそのまま押せなくなるため、時間切れで失敗として扱い、「サーバーから返事がありません」と出して押せるように戻す。卓の窓は、開き直したときにも押せる状態へ戻す。通信が戻れば、次の自動更新か「更新」で表示も元に戻る。
- 書き込みはすべて 1 本の順番待ち（スクリプトロック）の中で、読み直してから書く（2026-10-02。それまでは日程調整と見回り・描き直しだけだった）。対象は、卓の登録・保存・削除・まとめての変更、参加希望と興味あり、メンバーの予定の △× とメモ、日付メモ、メンバー、設定、Discord への送信、表示の描き直し。前は都合表の描き直し（十数秒かかる）の最中に付けた △× が消え、新規登録が 2 件重なると同じ ID と行に書いて片方が消えていた。30 秒待っても順番が来ないときは「少し待ってから、もう一度押してください」と出す。10 分おきの描き直しと見回りは、待ちきれなければ黙って次の回に回す。まだ防いでいないこと：同じ卓を 2 人が別々の窓で編集すると、後から保存した内容で上書きされる（窓を開いたときの更新日時と見比べれば止められる）。
- 「回答がそろいました」と「日程が決まりました」は、回答や決定を受けたサーバーがその場で送る。以前は画面から送っていたため、送る前に画面を閉じられると届かなかった（2026-09-29 の「新機動戦記ガンダムW」）。サーバーからの送信に失敗したときだけ、画面が送り直す。
- アイコンは Google Fonts（fonts.googleapis.com）の Material Symbols Rounded を、使う名前だけに絞って読み込む。読み込めない環境（社内の通信制限など）では、アイコンの場所が空白か英字の切れ端になる。ボタンの文字は残るので、操作はできる。
- 画面にアイコンを足すときは、`src/client/Console.html` の先頭の読み込みの `icon_names` にも名前をアルファベット順で足す。足し忘れると、そのアイコンだけ英字の切れ端になる。
- 自動更新は、画面を開いている人ごとに間隔ぶん Apps Script を呼ぶ。10 人が 1 分ごとにすると 1 時間に 600 回になる。重く感じたら、設定タブの「この端末」で間隔を延ばす。画面が隠れているあいだは呼ばないので、開きっぱなしの裏のタブが呼び続けることはない。
- 合言葉はブラウザの保存領域に覚えさせる。ブラウザのサイトデータを消すと入れ直しになる。共用の PC ではログアウトしておく。

```
npm install   （初めてのときだけ）
npm test
```

`npm run test:watch` にすると、ファイルを保存するたびに回し直す。VS Code なら拡張機能「Vitest」で、テストを画面から回せる。

- サンプル投入が重複しない

- 都合の印が表示の作り直し後も残る
- 登録タブからの新規登録で S004 が振られ、更新で ID と行数が変わらず、削除で行が減る。「開催」なのに開催日が無いと弾く
- 登録時の Discord 通知、開催前の知らせの 1 通まとめ・メンション・通知済みの印・二重送信の抑止、失敗時のアラートとログ
- トリガーの設定・二重設定の抑止・解除
- 表示月数 12・都合 366 日でも落ちない
- 開催日を文字列で、時刻を Date やシリアル値で手入力しても読める
- メンバー 0 人・卓 0 件でも表示が組める
- 使い方のページ。`?page=tutorial` で `client/Tutorial` を CSS と JS を差し込んだ形で返し、題が付き、アプリへ戻るリンク用にウェブアプリの URL を渡す。ほかの値では画面を返す。画面用データにウェブアプリの URL が載る
- ウェブアプリの入口。`doGet` が画面を返し、画面用のデータが揃い、都合の書き込みが通り、メンバーに無い名前・範囲外の日付・不正な印を弾く。アクティブなシートが取れない状況でも控えた ID から開ける
- メンバーの追加・更新・削除。重複名・区切り文字入りの名前・数字でない Discord ID を弾く。名前を変えると卓の GM・参加者と都合の印が追随する
- 都合表の「参」「GM」。卓の GM と参加者に自動で付き、その日は全員空きにならず、コンソールからもシートからも書き換えられない
- 空欄は参加できる。○ は書けず、旧い ○ は空欄として読み、作り直すとシートからも消える。誰も印を付けていない日は全員空き、△ の人がいれば「△あり」、× の人がいれば色が付かない。都合のドロップダウンに ○ は無い。カレンダーシートの凡例も「全員空き」
- 一括変更。参加者の追加と除外、開催日のずらし（開催前の知らせの印が消える）、GM の変更、状態の変更（Discord 通知 1 通）、削除。未選択・日付の無い卓を予定にする・日数でない値を弾く
- 卓 1 件の案内。1 通で送り、今日が開催前の知らせの日の卓なら開催前の知らせ済みになる。無い卓と送信失敗はエラーで返す
- 失敗の種類分け。429 は「Discord 側の制限」でツールの不具合ではない旨が付き、途中の記録には「N 秒後に送り直し」、打ち止めの記録には「送信失敗（種類）: 詳細（3 回目、打ち止め）」と出る。400 は「本文」でツール側の可能性を残し、404 は「Webhook URL」、5xx は「Discord 側の不調」、承認不足は「承認」、通信断は「通信」、それ以外は「原因不明」
- 画面から 1 回ずつ送る仕組み。1 回目が 429 なら「まだ送り直せる」と 3 秒の待ちを返しサーバーは待たない、2 回目は 8 秒、3 回目で駄目なら打ち止めで見当が付く、2 回目で通れば「OK（2 回目）」、400 は送り直さない、登録・変更・削除・一括・案内の本文、案内が通れば明日の卓は開催前の知らせ済みになり通らなければ印を付けない、URL が空なら送る前に断る、一括変更の返事に名前と操作の文が付く
- 送り直し。429 が 2 回続いても 3 回目で通り、間に約 3 秒と約 8 秒待つ、3 回とも 429 なら失敗で終わり 1015 の説明が付く、5xx も送り直す、400 と 404 は送り直さない、Retry-After に従い長すぎれば 15 秒に抑える、開催前の知らせも送り直して通れば通知済みになり 3 回とも失敗なら通知済みにしない
- Discord の送り方。ID の無い参加者や未登録の人が混ざっていても送れ、メンションは ID のある人だけ、全員 ID 無しでも送れる。送らなかったときも理由が通知ログに残る。404 と 400 と承認不足に見当が付く。桁のおかしい ID に印が付き、18 桁と未設定には付かない。送る JSON は本文 2000 字・embed 10 件・題 256 字・説明 4096 字の上限に収まる（12 卓・参加者 20 人でも）
- メンバーの予定をまとめて入れる。曜日で絞れる、卓の日は飛ばす、「入力済みは残す」の有無で上書きが変わる、空欄に戻せる。逆の期間・曜日なし・名前なしを弾く
- 設定タブ。自動通知の有効・解除、時刻を変えても見回りのトリガーは 1 本のまま時刻だけが変わる、Discord 以外の URL を弾く、空欄のままなら URL は消えず明示すれば消える、他人がシート側で設定した自動通知は解除せず案内する
- シリーズごとの通知。Discord 以外の URL と 0〜23 以外の時刻、シリーズ名なしを弾く。画面用のデータでは URL を伏せる。「基本のチャンネルにも送る」が OFF なら専用のチャンネルだけ、ON なら専用 → 基本の順に両方へ。設定の無いシリーズと単発の卓は基本のチャンネルへ。基本 20 時・シリーズ 21 時のとき、見回りは 19 時に何も送らず通知ログも増やさない、20 時に単発の卓だけを基本へ、21 時にシリーズの卓を両方へ、22 時は何も送らない。通知ログに送り先が残る。画面からは送り先を 1 か所ずつ送る。シリーズの接続テストは専用のチャンネルだけに送り、専用の URL が無ければ断る。削除の知らせと、同じシリーズのまとめ登録はシリーズの送り先へ、一括変更は基本へ。保存と同時の知らせも両方へ。設定を消すと基本のチャンネルと基本の時刻に戻る。旧い「毎日 1 回」のトリガーは 1 度だけ見回りに置き換わる
- 種類ごとのチャンネル。Discord 以外の URL と知らない種類を弾き、画面用のデータでは URL を伏せる。開催前の知らせは開催前の知らせのチャンネルへ送り、基本には流れない。シリーズ専用のチャンネルがある卓はシリーズへ、「基本のチャンネルにも送る」なら開催前の知らせのチャンネルにも。通知ログに「（開催前の知らせのチャンネル）」が残る。状態が「募集」の卓の登録・変更・案内・削除と、興味ありの人への参加確認は募集のチャンネルへ、開催の卓は基本へ。一括変更と種類の無い知らせ（日程調整など）は基本のまま。種類ごとのチャンネルだけに接続テストを送れ、URL が無ければ断る。外すと基本へ戻る
- 募集・調整の知らせの URL。募集の卓の登録には参加希望の入口、調整中の卓の登録には日程調整の入口として卓予定の URL が付く。開催の卓の知らせと削除の知らせには付かない。案内も募集・調整中の卓にだけ付く。日程決定の知らせにも付く。URL が取れないときは行ごと出さない
- 開催前の知らせの日時。何日前は 0〜30 の整数、時刻は 0〜23 を弾く（基本もシリーズも）。基本を 3 日前の 9 時台にすると、8 時は送らず 9 時に 3 日後の卓だけを送り、見出しは「3 日後は卓の日です」。開催前の知らせの日を過ぎた明日の卓は送らない。シリーズを当日の 12 時台にすると、11 時は送らず 12 時に「今日は卓の日です」で送る。同じ時刻・同じチャンネルでも「あと何日」が違えば 1 通ずつ分ける。案内を送ると、今日が開催前の知らせの日の卓だけ開催前の知らせ済みになる。状態の文言（送信済み・未送信・「M/D（曜） H 時台に送る」・自動通知が無効なら未設定）、シートのお知らせに送る日時が出る。旧い項目名「前日通知の時刻」は読み替え、書くときと整え直すときに名前を直し、何日前の行を足す。旧い並びのシリーズ通知シートも読め、整え直すと今の並びに 1 度だけ組み直す。セッションの見出し「前日通知」も「開催前の知らせ」に直る
- シリーズごとの通知の画面（ブラウザで確認）。設定タブで Discord（基本）→ 開催前の知らせ → シリーズごとの通知 の順に並ぶ。設定が無いうちは一覧と入力欄が隠れ、選ぶといまの送り先と時刻が出る。URL を貼るまで「基本のチャンネルにも送る」は選べない。書きかけは読み込み直しても残る。保存すると一覧に出て URL 欄が空き、候補に「（設定あり）」が付く。一覧の行を押すとそのシリーズを選ぶ。弾かれたら理由がボタンの横に出て入力は残る。登録の窓の「Discord に知らせる」は、基本の URL が無くても専用の URL があるシリーズなら付けられ、シリーズを消すとまた付けられない。送り先が 2 か所のとき、1 か所目が失敗しても 2 か所目へ送り、吹き出しとボタンの横に、届いた先と届かなかった先が出る。スマホ幅で横にはみ出さない
- 開催前の知らせの欄・「？」・はじめの 3 ステップ（ブラウザで確認）。基本の日時は「開催日の [1] 日前、[20] 時台」で入り、例えが出る。25 時は赤枠と理由が出て有効にしない。有効にすると何日前と時刻が届き、ボタンが「この日時で保存」に変わり、そのあとは日時だけを保存する。表示の「保存」は日時を送らない。シリーズは「開催前の知らせは基本と同じ日時（前日の 20 時台）」が付いていて、外すと基本の値の入った欄が出る。40 日前は送らず理由が出る。一覧に「3 日前の 22 時台」。「？」は URL の欄に 1 つずつあり、押すと取り方が出て、Esc と × で閉じ、スマホ幅でも画面に収まる。卓予定に Discord の設定の行が出ない。内訳に「開催前の知らせ M/D 20 時台に送る」。はじめの 3 ステップは、そろったあとは出ず、「使い方」の隣のボタンでカレンダーに出て（3 つとも済み。押してもボタンの見た目は変わらず、カレンダーのタブが選ばれる）、スマホは上の帯にある旗のボタンで出て、390 px と 360 px でも上の帯に収まり、閉じる・開くボタンが付き、読み込み直しても残り、× で消える
- 「募集を始める」「日程調整を始める」とはじめの 3 ステップの切り替え（ブラウザで確認）。カレンダーの「卓を登録」の隣に同じ高さ（44 px）で 1 段に並び、募集・調整タブの見出しからは外れている。「募集を始める」は新規・状態は募集で開き、開催予定の月が出て開催日と参加者は隠れる。「日程調整を始める」は状態が調整中で、候補の期間が出る。390 px と 360 px では 2 つが横に並び、横にはみ出さない。はじめの 3 ステップは、出しているあいだボタンが押してある見た目になり、もう一度押すと閉じ、閉じたあとは読み込み直しても出ない。× でも閉じる。ほかのタブで押すとカレンダーに移って見せる。スマホの旗のボタンも同じ
- 状態ごとの手順（ブラウザで確認）。新規の窓で状態を選ぶと、開催・募集・調整中それぞれの 3 段が出て 1 段目が「いまここ」、中止は一言だけ。調整中では保存ボタンが「登録して候補日を選ぶ」になり、登録するとそのまま候補日を選ぶ窓が開く。候補日を出した調整中の卓と、希望が付いた募集の卓を開くと 3 段目が「いまここ」でボタンは「更新」。募集・調整のカードに「次にすること」が出る
- 返事が返ってこないとき（ブラウザで確認）。書き込みの返事を止めると、いったんは窓のボタンが押せなくなるが、窓を開き直すと押せる。時間切れのあとは押せるように戻り、「サーバーから返事がありません」と窓と吹き出しに出て、窓が開き直る。通信が戻って読み込み直すと、消えていない卓は元に戻る。ふつうの削除はこれまでどおり効く
- 募集・調整まわりの直し（ブラウザで確認）。卓予定では募集中・調整中が今日・明日より上に出て、背景の色が違う。募集・調整タブの見出しのボタンで、卓があっても新しく始められる。募集のカードの「開催にする」で状態が「開催」の窓が開き、保存の前に興味ありの人をどうするか聞く。チェックした人は参加者に入り、しない人は外れる。メンバーの予定では、卓を選んだ時点でその卓の人だけになり、「どれかの卓に入っている人だけ」はどの卓にも入っていない人を隠す（重ねられる）。日が未定の卓の帯を押すと同じように絞り、もう一度押すと戻る。「あなた」を変えると、その人の絞り込みに切り替わる。「解除」で戻る。表は幅いっぱいに広がる
- 項目ごとの説明・文字サイズ・名前（ブラウザで確認）。募集・調整とメンバーの予定から「使い方」の折りたたみが消え、見出しや操作の横に「？」が付く。マウスを載せると説明が出て、離すと消え、押しても出て、Esc で消える。吹き出しは PC でもスマホでも画面に収まる。文字サイズは小・中・大で見出しが大きくなり、大でも横にはみ出さず、開き直しても覚えていて、小に戻せる。名前は確かめる窓のあとに変わり、左上とシートの名前がそろう。同じ名前なら知らせる
- 「その日の卓」の 2 行（ブラウザで確認）。卓と祝日が重なる日は、祝日が 2 行目に出る。PC でもスマホでも折り返して「…」で切れず、長い名前を入れると高さが伸びる
- 募集の期間と 2 つの知らせ（ブラウザで確認）。登録の窓で「開催」には期間の行が出ず、「募集」にすると開催日が消えて「開きたい期間」、「調整中」にすると同じ欄が「候補の期間」になる。旧い「開催予定の月」の選択は無い。期間を入れて保存すると卓に期間が入り、募集・調整タブのカードに「10/16（金）〜10/30（金）」と出る。片方だけの期間は画面で断る。設定タブの「そのほかの知らせ」は、期間前の催促が ON・開始直前の知らせが OFF・30 分で始まり、3 分は断ってチェックが戻り、45 分なら ON にできて「見回りを 5 分ごとに」と返る。スマホ幅でも横に溢れない
- 種類ごとのチャンネル（ブラウザで確認）。設定タブで Discord（基本）の次に並ぶ。決めていないうちは「（基本のチャンネルと同じ）」で、接続テストと外すは押せない。空のまま保存すると案内が出る。保存すると伏せた URL が出て欄が空き、接続テストはそのチャンネルだけに送る。基本の URL が無くても、募集の卓の登録では「Discord に知らせる」が付けられ、送り先に「（募集のチャンネルへ）」と出る。状態を開催に変えると付けられない。開催の卓の「Discord に通知」も押せない。外すと基本に戻る。「？」は 4 つの URL の欄に 1 つずつ
- 祝日。2026 年の元日・成人の日・春分・秋分、5/3 が日曜のときの 5/6 振替休日、9/22 の国民の休日、2025 年の振替休日・海の日・スポーツの日。都合シートの曜日に「祝」が付く
- 描き直しは「あとで」。登録 1 回のシート操作が 60 回（改善前 423 回）で、その時点ではカレンダーシートは変わらず、印が付き、10 分おきのトリガーが 1 本だけできる、返事の data に登録した卓が入る、トリガーが走るとカレンダーシートに出て印が消える、印が無ければ何もしない、足した直後のメンバーの予定も書ける、予定の日数を変えると都合シートは即座に作り直す、シートを開いたときの描き直しでも印が消える
- 過ぎた卓の自動終了。保存の時点で過ぎた卓は終了になる、今日の卓は「開催」になり終了にはしない、表示の作り直しでも終了になる、二度目は何もしない、カレンダーに「済」付きで残る、中止の卓も残る、一覧からは消える、設定で止められる
- 管理者（サーバー）。決める前は全員が管理者あつかいで、シートの URL も渡す。短い合言葉と 2 つの入力違いは弾く。決めると証が返り、決めた人が名簿に載って「設定」シートの「管理者」に入る。管理者でなければ isAdmin は false で URL は空。メンバーの追加・削除、設定・知らせ・シリーズ・名前の変更、みんなの合言葉の変更、まとめて変えること、卓の削除は「ADMIN:」で断る。自分の都合は誰でも入れられ、ほかの人の都合と予定メモは管理者だけ。合言葉が合えば管理者になり名簿に足され、違えば断る。名簿から外せるが、最後の 1 人は外せない。合言葉を変えると古い証は通らず、新しい証なら通る。シートのメニューから空で決め直すと、全員が操作できる状態に戻る
- 管理者（ブラウザで確認）。設定に「管理者」の区分が出て、はじめは「まだ決まっていません」。2 つの入力が違えば断る。決めると「あなたは管理者です」になり、名簿に自分が載り、ブラウザが証を覚える。証を捨てて読み直すと「あなたは管理者ではありません」になり、シートの入口が消える。管理者の操作をすると合言葉の窓が出て、断られた理由が出る。違う合言葉は断り、合えば窓が閉じて、断られた操作がやり直される（名前が変わる）。別の人が合言葉を入れると名簿に足され、2 人以上なら外すボタンが出る。スマホでも同じに出て、横に溢れない
- 合言葉。決める前は誰でも開け、ログインは断られる。短い・2 つが違う合言葉は弾く。決めると証が返り、合言葉そのものは保存されない。二度目は決められない。証が無いか違えば画面用のデータを返さず、書き込みの関数（登録・削除・都合・希望・メンバー・一括・メモ・設定・Discord・合言葉の変更）はすべて「AUTH:」で弾き、証があれば通る。違う合言葉は断り、合えば同じ証が返る。変えるにはいまの合言葉が要り、変えると古い証は無効で新しい証だけ通り、古い合言葉では入れない。10 回続けて間違えると合っていても待たされ、10 分たてば入れる。シートのメニューで決め直すと前の証は無効になり、短ければ変えず、キャンセルなら変えない
- シリーズ。シリーズ名が卓に残り画面用データに載る。複数日をまとめると重なる日は 1 つにして日付順に登録され、名前は末尾の数字を進め、GM・参加者・場所・時間は同じで、返事のデータにそろう。数字の無い名前は 2 回目から「#2」。既存の卓・募集・読めない日は弾く。一括でシリーズを付ける・外す。一覧シートにシリーズの列が出る。古いシートに「シリーズ」の見出しが足される。直してもシリーズは残る
- 参加の確認。興味ありの人がいない卓と募集中でない卓には送らない。興味ありの人だけを呼び、ID の無い人は名前で書き、参加希望の人は呼ばない。文に返事の仕方とウェブアプリの URL、期間、送った人が入り、卓の内容も添える。一言を添えると名前付きで挟まり、返事の案内はその後ろに来る。長すぎる一言は弾く。送った日時が卓に残って画面用データに載り、募集のまま直しても残り、予定にすると消える。古いシートに「参加確認」の見出しが足される
- 募集。状態が 募集・調整中・開催・終了・中止 の 5 つ。募集の卓は期間だけで登録でき、期間が空でもよく、片方だけの期間は弾く。開催日の無い「開催」は弾いて募集を案内する。参加希望と興味ありは片方だけ付き、取り消せて、Discord には送らない。名前なし・すでに参加者・募集中でない卓を弾く。都合の相手に参加希望の人が入る。一覧に期間と参加希望の列、管理に「うち募集」と「希望」、お知らせに期間と希望の人数、案内の本文に期間と参加希望が出る。「開催」にすると参加希望の人が参加者に移り、希望と期間が空になり、返事に加えた人が入り、都合表に「参」が付く。一括変更で開催にしても同じで興味ありは動かない。過ぎた卓は「終了」。古い見出しに列が足される。並びは日付あり → 期間の早い順 → 期間未定
- 募集の期間（サーバー）。旧い「2026/05 後期」の行は、シートを整え直す前でも 5/16〜5/31 の期間として読め、整え直すと「期間」の列へ移って「募集時期（旧）」は空になる。見出しは 募集時期（旧）・期間・期間前の催促・開始直前の知らせ。募集で入れた期間は調整中にしてもそのまま残り、募集でも調整中でもなくなると消える
- 期間前の催促（サーバー）。既定は ON。開催前の知らせ（時刻）より前の見回りでは送らず、時刻になると、明日から期間の始まる募集中・調整中の卓を 1 件ずつ送る。本文は募集と調整で言い分け、GM をメンションし、卓予定の URL を添える。送った卓に印が付き、まだ先の卓には付かない。同じ日に 2 回走っても送り直さず、期間を変えると印が消えてもう一度だけ送る。OFF にすると送らない
- 開始直前の知らせ（サーバー）。既定は OFF・30 分前で、OFF のあいだ見回りは毎時。5〜720 分の外は弾く。ON にすると見回りが 5 分ごとになり、40 分前では送らず、20 分前に「あと 20 分で…」を GM と参加者へメンション付きで送る。5 分後の見回りでは送り直さない。開始を少し過ぎたところなら「まもなく…」で送り、30 分過ぎていれば送らない。開始時刻を変えると印が消える。OFF に戻すと見回りも毎時に戻り、送らなくなる
- 募集から開催へ（サーバー）。参加希望の人は参加者に入り、興味ありの人は画面で選ばれた人だけ参加者に入り、残りは一覧から外れる。加えた人と外した人は返事の文に出る。募集のままなら興味ありはそのまま残る
- 卓予定の名前（サーバー）。空の名前と 80 文字を超える名前を弾く。変えると画面用のデータにも新しい名前が載り、元に戻せる
- 日程調整。「日程調整」シートとセッションの「候補日」の列ができる。候補日が無い・過ぎた日・調整中でない卓・参加者のいない卓は弾く。候補日は重なりを除いて日付順に残り、時間も入り、出した人（GM）の ◯ が最初から付き、画面用データに候補日と回答が載る。GM・参加者でない人、候補日でない日、◯ × 以外の回答、名前なしは弾く。× の人がいれば決まらず、空で送ると回答の行が消える。選び直すと外した日の回答は消え、残した日の回答は残り、足した日に出した人の ◯ が付く。シートのお知らせに候補日の数と未回答の人数が出る。Discord の知らせに呼びかけ（ID の無い人は名前）・候補日・時間・答え方が入り、添える卓の内容にも候補日が出る。全員が答えると ready を返し（そろったあとの答え直しでは返さない）、全員が ◯ の日があっても自動では決まらない。そろった知らせは GM だけを呼び、候補日ごとの ◯ の数を並べる。GM が選んだ日に決まり（候補日でない日は弾く）、状態は「開催」、開催日と時間が入り、候補日・期間・回答は片付き、都合表に「参」「GM」が付き、返事のデータにも決まった日が載る。決まった知らせに日付と呼びかけが入る。決まった卓ではもう始められず、日程調整の知らせも送れない。参加者が出してもその人の ◯ が付き、やめると候補日と回答が消えて卓は調整中のまま、始め直すと前の回答は残らない。調整中のまま直しても候補日は残り、状態を変えると消え、卓を消すと回答も消える。カレンダーと都合シートに候補日が出る
- 調整中。候補の期間を逆に入れても前後を直して残り、画面用データに載る。片方だけの期間と読めない日は弾き、期間は空でもよい。「~」区切りや逆順も読み、片方だけは読まない。お知らせに卓と期間、カレンダーの期間の日それぞれに ◇、都合表の期間の行に「調整:」、一覧の「あと」と管理に期間が出る。募集から調整中にすると参加希望の人が参加者に移り、期間はそのまま残る。予定にするには開催日が要り、予定にすると期間は消える。一括でも調整中にでき（開催日は要らない）、予定にすると期間が消える。期間を過ぎた調整中はお知らせに出て、自動では変えない。募集も調整中も期間の始まりで並べる。案内の本文に期間と調整中が載る。古いシートに「期間」の見出しが足される。旧い版の「調整中」（期間なし）はそのまま期間未定の調整中として読む
- 状態の作り直し。状態は 募集・調整中・開催・終了・中止 の 5 つで「予定」は無い。旧い版の「予定」は読み込み時に「開催」として扱い、シートを整え直すとセルの値も書き換わる。開催日を過ぎた卓は終了になり、当日はそのまま開催で残る
- シリーズ。最終日を保存して読み出せる。読めない最終日は空にする。単発の卓から「続けて登録」すると前の回にも同じシリーズ名が入り、返事にその旨が出る。すでにシリーズがある回の名前は書き換えない
- 入力規則の整え直し。古い版のドロップダウンが残ったまま「調整中」を書こうとしても、版が古ければ書く前に入力規則を作り直して版を控え、版が新しければ整え直さない
- 日付メモ。書けて書いた人が残る、書き直しても行が増えない、カレンダーシートに出る、空にすると消える、読めない日付と 500 文字超を弾く
- 予定メモ。書けて返事のデータに載る、書き直しても行が増えない、同じ日に別の人のメモも持てる、卓に入っている日にも書ける、都合シートのセルのメモに出る、空にすると消えてシートからも消える、名前なし・メンバーに無い名前・読めない日付・200 文字超を弾く、名前を変えると追随する、印を変えてもメモは残る

ブラウザ画面は、モックが作ったデータを `google.script.run` の代わりに流し込み、Chromium（Playwright）で PC 幅とスマホ幅の両方を描画して確かめた。見たのは次の点。

- 5 つのタブ（カレンダー・募集・調整・メンバーの予定・メンバーの登録・設定）が表示され、カレンダーは左 7 右 3 の 2 枠になる
- アイコン。Material Symbols Rounded のフォントが読み込まれ、タブのアイコンは英字でなく正方形の図で描かれる。アイコンはすべて読み上げない印（aria-hidden）が付き、アイコンだけのボタン（月送り・テーマ・更新・ログアウト・鉛筆）には名前がある。テーマのボタンは月と太陽で切り替わり、開閉のボタンは矢印と aria-expanded が切り替わる。PC 幅でもスマホ幅でもタブははみ出さず、スマホではアイコンが名前の上に来て、ヘッダーは 1 行に収まる
- カレンダーのアイコン。調整中の期間の日はアイコンだけで名前の札は出ず、名前はマウスを載せたときの文と読み上げ用の名前にある。予定の卓の札にはアイコンと名前が出る。アイコンの凡例は「日をタップすると内訳が出ます」のすぐ後ろにあり、PC 幅では同じ行の右側に並び、8 種がそろう
- 日程調整の画面。調整中のカードに「日程を調整する」が出て、押すと候補の期間の日が並ぶ窓が開き、各日に GM・参加者の予定が出る。選ぶまで送れず、「全員空きの日だけ」で絞れ、選んだ日数が出る。送るとサーバーに候補日・時間・出した人が届き、窓が閉じて Discord に日程調整の知らせを送り、カードに候補日の行と ◯ の人数が出る。「調整をやめる」で回答欄が消え、始め直せる。カレンダーでは候補日だけにアイコンが出て、卓予定に回答待ちと未回答の人、未回答の本人には「あなたの回答を待っています」が出る。内訳の「回答する」で募集・調整タブへ移る。× を押すと × の人に入り、同じ印をもう一度押すと取り消す。GM・参加者でない人にはボタンが出ない。最後の人の ◯ で決まり、Discord に決まった知らせを送り、吹き出しに「日程が決まりました」、卓は日程調整中から消えて予定になり、決まった日に予定の札が出る。スマホ幅でも窓とカードははみ出さない
- どの日でもいい（サーバー）。GM・参加者でない人、名前なし、調整中でない卓、◯ 以外の印は弾く。押すと候補日すべてに ◯ が付き、× を付けていた日も ◯ に変わる。行はすでにあるぶんを書き換え、足りないぶんだけ増える。ほかの人の回答は動かない。空で送ると自分の回答だけ全部消える。全員の ◯ がそろえば、いちばん早い候補日に決まって「参」が付き、候補日と期間は片付く。過ぎた候補日には付けず、過ぎた日しか無ければ断る
- どの日でもいい（ブラウザで確認）。日程調整中のカードの見出しの右にボタンが出る。× を付けた日があるときは確かめる窓が出て、進むと候補日すべてが ◯ になり、1 日ずつの ◯ も点き、ボタンが押された見た目になる。もう一度押すと確かめてから自分の回答だけが消え、ほかの人の回答は残る。スマホでも同じに出て、横に溢れない
- 募集・調整タブ。募集中 1 件と日程調整中 1 件が分かれて並び、タブの件数は 2。調整中のカードに候補の期間と「候補日をカレンダーで見る」が出て、参加希望のボタンは無い。押すとカレンダーに移り、その卓の候補の期間に枠が付く。調整中が 0 件なら「調整中の卓を登録」が 1 つ出て、押すと状態「調整中」の登録の窓が開く
- レイアウト。PC 幅（1300 px）とスマホ幅（400 px）のどちらでも、5 つのタブでページが横にはみ出さない。予定表を横に送っても、日付・曜・その日の卓の 3 列は同じ位置に留まって重ならない（メンバー 18 人で確認）。ヘッダーとカレンダーの上の段のボタン・選択欄は高さ 36 px にそろう。登録の窓は、中を下まで送っても題が上端、保存の列が下端に残る。吹き出しは窓より手前に出る。スマホのヘッダーは 1 段で 56 px、「卓を登録」は 56 px の浮かぶボタン
- 更新と自動更新。開いてデータが届くまで骨組みが出る。時刻が見え、自動更新中の緑の点が付く。「更新」を押すと回る印が出てボタンが押せなくなり、裏で足した卓がカレンダーに出て、吹き出しに「最新の状態にしました（時刻 時点）」、変わっていなければ「変更はありません」と出る。自動更新は間隔が過ぎると読み、変わっていなければ描き直さず、変わっていれば描き直して「ほかの人の変更を反映しました」と出る。間隔の前・窓を開いているあいだ・文字を入力中・書き込みの返事待ちのあいだは読まない。描き直しても日付メモの書きかけは残る。読み込み中に押した予定の印は、古い読み込み結果で戻らない。設定で「しない」にすると読まず点も消え、ほかのアプリから戻ると 1 分以上経っていれば読む。見た目をダークにすると保存され、「端末の設定に合わせる」で戻る
- 窓と確かめる窓。窓を開くとヘッダーと本文は触れず（inert）、スクロールも止まり、入力欄にフォーカスが入る。Esc で閉じると、フォーカスは開いたボタンに戻る。卓の削除では確かめる窓が上に重なり、フォーカスは「やめる」、進むボタンは赤い。Esc は確かめる窓だけを閉じて削除はせず、「削除する」で消えて両方の窓が閉じる。設定タブのログアウトも確かめる窓を通り、「やめる」ならログアウトしない
- 「あなた」未選択。枠が水色になり、参加希望などを押すと吹き出しで知らせて「あなた」にフォーカスが移る
- カレンダーの日。マスはボタンで、読み上げ用の名前に日付と要約が入る。Enter で選べ、描き直してもフォーカスは同じ日に残る。見えているアイコンはすべて正方形で描け、使っているアイコンはすべて読み込みの一覧にある
- ＋卓を登録。日を選んでいなければ「卓を登録」で、押すと開催日は空の窓が開く。登録の窓では開催日が卓の名前のすぐ下（GM より上）にある。日を選ぶとボタンが「10/9 に卓を登録」のようになり、押すとその日が開催日に入った新規登録の窓が開き、登録するとその日の卓としてサーバーに届く。同じ日をもう一度押して選択を外すと、ボタンの名前も戻る
- 使い方のページへのリンク。ウェブアプリの URL が分からないうちは出さない。分かると、PC ではカレンダーなどのタブと同じ並びの、設定のすぐ隣に名前付きの「使い方」が出る。スマホでは上のバーに名前付きで出て、バーは 1 段のまま収まる。設定タブとログインの窓にも出て、どれも新しいタブで開く
- 画面の並びと導線。内訳が「卓予定」より上にある。メンバーも卓も無いときは「メンバー → Discord → 予定」の 3 ステップの案内がこの順で出る。「メンバーを登録」で登録タブへ、「Discord を登録」で設定タブの Webhook URL の欄へ移れる。読み直して両方そろうと消える
- 同じ日の重なり。開催日と GM を入れると、同じ日に別の卓へ入っている人を注意に出す。重なりが無ければ出ない
- シリーズの画面。単発の卓から「続きを登録」を押すとシリーズ名と最終日の欄が出て、保存するとシリーズ名・最終日・前の回の ID がサーバーに届く。シリーズ名が空なら最終日の欄は出ない。募集のときは参加者の欄を出さない
- 「あなた」のプルダウン。選択肢の文字は本文と同じ色で、背景も塗る（黒い帯の上でも読める）
- 開いた瞬間の表示。読み込んだ内容をこの端末に控え、次に開いたときは返事を待たずにそれを描く。そのあとで最新を読み直す。ログインを求める状態になったら控えは消える
- 配色のコントラスト。ライトとダークのそれぞれで、本文・補足・リンク・主ボタン・土日・全員空き・×・メモ・参・吹き出し・上のバーの文字など 33 組を測り、文字は 4.5、フォーカスの枠と点は 3 を超える
- スマホ幅の組み替え。タブは画面の下に固定され、名前は切れずに隣と間が空く。ヘッダーは 1 段。「卓を登録」は下のタブの上に浮かぶ。日を選ぶまで内訳は出ず、下のほうの日をタップすると内訳が見える位置まで送られる。カレンダーを左になぞると次の月。窓は画面の下から出る全幅のシート。横にはみ出さない
- 登録・変更の窓。「この日に卓を登録」で窓が開いてその日が入り、後ろのカレンダーはそのまま。登録を押すと窓が閉じて吹き出しに「保存しています」、押した瞬間にカレンダーへ出て、返事は吹き出しに出る。内訳の「編集」で変更の窓が開き、変更として送って閉じる。Esc と「閉じる」でも閉じる。サーバーが断ると入力を残したまま窓が開き直って理由が出て、仮に出した卓は消える。「卓を登録」は空の窓。スマホ幅（400 px）でも窓は画面に収まり、参加者のチェックは横に並ぶ
- メンバーの予定。集計と卓×メンバーの表は無い。名前の下に GM・PL の数が出て、卓の多い人から左に並ぶ（同数なら GM の多い順）。まとめて入れる・絞り込みに ○ は無い。自分のマスは 空 → △ → × → 空 と変わる。「表示中の全員が空いている日」で絞れる。カレンダーでは全員空きの日が緑になり、凡例に ○ は無い。「卓をまとめて変える」を開くと卓の一覧が出て、行のタップで選べ、「編集」で変更の窓が開く
- 右上の卓予定をタップすると日が選ばれ、内訳に卓と「Discord に通知」ボタンが出て、押すと結果が残る
- 「続きを登録」で名前の数字が進み、翌日の日付と GM が入った新規登録になる
- メンバーの予定のタップで印が変わり、「参」「GM」のマスは変わらない。「まとめて入れる」で土日だけに △ が入る
- テーマのボタンでダークに切り替わり、保存され、開き直しても保たれる
- 設定タブで自動通知を有効にすると緑の表示に変わり、URL を保存すると入力欄が空になり、接続テストの結果が出る
- 日付メモ。カレンダーのマスに 📝 が出て、書くと札が出て、消すと消える
- 設定タブの送信記録に成功・失敗・送らずの 3 行が出て、失敗と送らずに色が付く。メンバータブで桁のおかしい ID に印が付く
- 3 回とも失敗したときの画面。最終表示が「送信失敗（Discord 側の制限）: …」で始まり、「このツールの不具合ではありません」と詳細（HTTP 429 error code: 1015、3 回試行）が入る。途中の待ち表示と吹き出しにも同じ旨が出る
- 日時の表記。日付型でも文字列でも「2026/09/15（火） 21:23」になり、通知ログは日付型で書かれ、送信記録・開催前の知らせ・日付メモの日時が同じ形で出る
- 送信の進み具合。登録すると「シートに保存しています…」→「Discord に送信中…（1 回目／最大 3 回）」→「混雑しています。2 秒後に 2 回目…」と秒が減り →「Discord に送りました（2 回目で成功）」の順に出て、保存ボタンが戻る。内訳の「Discord に通知」と設定タブの接続テストでも同じ流れになる
- 即時反映。登録を押して 120 ms 後にはカレンダーに出ていて、返事のあとも残り仮の ID は消える、登録 1 回で getConsoleData を呼ばない、削除も押した瞬間に消える、メモも押した瞬間に札が出る
- 終わった卓。カレンダーに「済」と「中止」の札が出て、マスが灰色になり、内訳では終了の卓に通知ボタンが出ない。「編集する卓」の一覧に終了卓は出ないが、ほかの画面から開けば更新として保存される（新規が増えない）
- メンバーの予定で土曜・日曜・祝日の行に色が付き、「土日祝」の絞り込みで行が減り、「自分だけ」で列が減り、スマホ幅でドラッグすると横にスクロールする
- メンバーの予定の「卓をまとめて変える」から一括変更が走り、「終了・中止も表示」で行が増える
- 列の並び。卓の多い人から順に左へ来て（同数なら GM の多い順、それも同じなら登録順）、上下 2 つの表で揃う。終わった卓は数に入らない。卓を足すと並びが追う。絞り込んでも順は崩れない。切り替えを外すと登録順に戻り、開き直しても覚えている
- メンバーを追加すると「あなた」の候補に増え、フォームが表の上にある
- 募集。タブがカレンダーの次に件数付きで並び、カードに期間・参加希望の人が出る。「あなた」未選択なら吹き出しで止まり、参加者にはボタンが出ず、参加希望済みの人は強調されて「取り消す」が出る。興味ありに切り替えると押した瞬間に付け替わり、サーバーに種類と名前が届き、取り消すと両方空になる。Discord へは送らない。卓予定の「募集中」をタップすると「募集・調整」タブが開き、卓の一覧に期間が出る
- シリーズ。候補にサンプルのシリーズが出て、新規なら「日を足す」が出る。シリーズを選ぶと名前が「#2」になり GM・参加者・場所・時間が入って引き継いだ旨が出る。日を 3 つ並べると「3 日分」の案内が出て × で外せ、登録を押した瞬間に 3 回分が仮に出て、サーバーに 3 日とシリーズが届き、返事のあと 4 回そろって仮の ID は消える。内訳の「この日に続きを登録」でシリーズを選ぶと、日付・シリーズ・「#5」・GM の入った登録画面になる。既存の卓ではシリーズが入り「日を足す」は出ない。卓の一覧にシリーズの列、一括変更に「シリーズを変更」の欄が出る
- 参加の確認。興味ありの人がいれば「興味ありの人に聞く」が押せ、押すと一言を添える窓が開いて相手の名前が出る。閉じれば送らず、送るとサーバーに卓・自分の名前・一言が届き、「確認文を送りました（日時）」がカードに残る。興味ありの人がいなければ押せない
- 調整中。候補の期間の日に ◇ の札が出て期間の外には出ない。卓予定に卓と期間が出て、内訳に候補日として並ぶ。卓予定の行をタップすると「都合を見る卓」がその卓になり、期間の日に枠が付く。メンバーの予定の期間の行に「調整: 卓名」が出て、卓の一覧に期間が出て、一覧の「編集」で期間の入った窓が開く。フォームで調整中にすると開催日が隠れて候補の期間が出て、片方だけなら断り、逆に入れても直して送り開催日は空。開き直すと期間が入り、登録した卓の期間にも ◇ が出る
- 予定メモ。「あなた」未選択なら鉛筆のボタンが出ず、選ぶと自分の列の全マスに出る。鉛筆で窓が開き、印は変わらない。書くと押した瞬間にマスへ点が付いて文はマスに出ず、マウスを載せると吹き出しに出て外すと消える。サーバーに名前・日付・文・証が届き、開き直すと入っていて「消す」が出る。書き直せて、印を変えてもメモは残り、「消す」で点が消える。ほかの人のメモも点だけで鉛筆は無く、載せると出て、タップすると全文の吹き出しが出て印は変わらない。参/GM のマスにも自分なら鉛筆が出て、印を残したまま点が付く。内訳のメンバーの予定にも点が付き、載せると出て、タップでも出る
- 合言葉。まだ無ければ「最初の合言葉を決める」の窓が出て、決めるまで何も描かない。短い・2 つが違う入力は断られ、決めると画面とログアウトが出て証を覚える。開き直しても求めず、メモと都合の書き込みに証が添えられる。ログアウトで窓が出てデータと証が消え、違う合言葉は断られ、合えば戻る。設定タブで変えるといまの合言葉が違えば変えず、変えると自分は新しい証に置き換わり、古い証のブラウザは開き直すとログインを求められ、古い合言葉では入れず新しい合言葉で入れる。開いたまま合言葉が変わった人は、書き込みで断られた時点で証を捨てて窓が出て、入れ直せば続きが使える
- 登録の窓（募集）。新規は「開催」で開催日の行が出て、状態を「募集」にすると開催日が隠れ、今月から 12 か月の「開催予定の月」と前期・後期が出る（既定は来月の前期）。募集の卓を開くと時期と参加希望の人が入り、「開催」に変えると案内が出て、保存を押した瞬間の仮表示でも参加希望の人が参加者に入る。サーバーへは開催日と時期なしで送り、窓が閉じて吹き出しに加えた人が入り、タブの件数が減る。当日の卓の札に「開催」が付く

実機で最初に確かめる点は 4 つ。ここが通れば、あとはモックで確かめた範囲に入る。

- 初回承認が通る
- ウェブアプリの URL が開いて、合言葉を決めたあとにシートのデータが出る。別のブラウザで開くと合言葉を求められる
- Discord に実際に届く
- 翌日、自動通知が届く

## 手元で動かす（開発サーバー）

`npm run dev` で開発サーバーを立て、`http://localhost:5173/` を開くと、Google のシートもログインも無しで卓予定が動く。開発にも、画面を見せるのにも、スクリーンショットや動画にも、これを使う（2026-10-03 まではこれと別に、ファイルで開く「デモ画面」を組み立てていた）。

- 中身は本物の画面（`src/client/`）とサーバー側（`src/server/`）。サーバー側を Apps Script の模型（`test/mock_gas.js`）ごと画面の中に埋め込み、ブラウザの中だけで動かす。だから卓の登録・参加希望・日程調整・△× などは本番と同じに動く。Discord へは送ったことにするだけで、どこにも届かない。
- `src/` や `dev/` のファイルを保存すると、開いている画面が読み込み直される。Apps Script に送らなくても、画面とサーバー側の直しを確かめられる。
- データは開くたびに作る架空のサンプル。メンバー 6 人（ひより・ソラ・こまち・レン・ミナト・ユズ）、シリーズの卓 4 回（1 回は終了）、単発の卓 4 件（今日・明日を含む）、募集 2 件（参加希望と興味ありつき）、日程調整 1 件（候補日と回答つき）、曜日ごとの △×、予定メモと日付メモ。日付は開いた日から数えるので、いつ開いても今の月の画面になる。
- 操作はどこにも保存されない。開き直すか、左下の「最初に戻す」で最初の状態に戻る。合言葉は聞かない。シートを開くボタンとログアウトは隠してある。
- 使い方のページは、本物と同じく `/?page=tutorial`。「アプリを開く」はアプリ（`/`）へ戻る。
- URL の後ろに付けると見た目を選べる（`&` でつなぐ）。`?clean` は左下の札を隠す（スクリーンショット用）。`?theme=dark` か `?theme=light` で配色、`?me=こまち` で「あなた」、`?tab=recruit` で最初の画面（cal・recruit・avail・members・settings）。例: `http://localhost:5173/?clean&theme=dark&tab=recruit`
- 組み立て方は `dev/pages.js`。サンプルの中身は `dev/seed.js` で変えられる。`npm test` の `test/dev.test.js` が、サンプルが作れるかを確かめる。
- 開いてから画面が出るまで 1 秒ほど。サンプルは、最初に画面がデータを読みに来たときに作る。
- スクリーンショットは `npm run screenshots` で `promo/images/` に撮る（開発サーバーをその場で立てて撮る。リポジトリには入れない）。初めてのときは先に `npx playwright install chromium` でブラウザを入れる。PC（1440×900 を 2 倍）はカレンダー（明・暗）・卓の登録・募集・調整・メンバーの予定・設定、スマホ（390×844 を 3 倍）はカレンダー（明・暗）・募集・調整・メンバーの予定。札と吹き出しとスクロールバーは写さない。同じ名前で上書きする。
